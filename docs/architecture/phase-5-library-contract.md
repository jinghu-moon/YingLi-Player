# Phase 5 视频库与安全文件操作契约

## 查询 DSL

`LibraryQuery` 由关键词、快捷分组、`SortSpec`、扁平 `FilterExpression`、稳定游标和页大小组成。

- 关键词先 `trim`，最多 120 字符；空关键词跳过名称、文件夹和标签的模糊匹配。
- 排序字段为名称、最近添加、时长、播放次数，均支持升降序，媒体 ID 是最终稳定排序键。
- 多标签默认 AND，可选 ANY；排除标签始终生效。时长、最小宽度和后缀条件与标签条件共同使用 AND。
- 筛选表达式使用 URL 编码键值格式持久化；序列化集合先排序，round-trip 结果稳定，不支持表达式嵌套。
- 游标保存当前排序值和媒体 ID。游标对应项消失时返回可重试结果，不从错误偏移继续产生重复项。

## 显示偏好

- 视图模式：Grid、List、Waterfall。
- `thumbnailScale` 独立存储，范围 0.75–1.50；改变布局或密度不修改查询条件。
- Grid 标题最多一行，List 最多两行；观看进度使用白色层级与可读百分比语义。
- Compact 使用 Modal Bottom Sheet，宽屏将相同筛选内容放在 320dp 侧面板。

## 文件操作矩阵

| 来源与目标 | rename | move | trash/restore | 失败保护 |
| --- | --- | --- | --- | --- |
| `file://` 同卷 | 原子 rename | 原子 move | 移入相邻 `.Trash/YingLi` | 同名时不覆盖 |
| `content://` 同授权树 | `DocumentFile.renameTo` | 先复制，完整写入后删除源 | 返回需要系统授权 | 删除源失败时删除目标副本 |
| 跨 scheme/卷离线 | 拒绝 | 可恢复失败 | 可恢复失败 | 不删除源文件 |

所有操作在 I/O Dispatcher 执行；领域结果只包含稳定错误分类，不记录 URI、路径或异常消息。

## 回收站策略

- 默认保留 30 天，可配置范围 1–365 天。
- 重复删除通过媒体 ID 主键保持幂等。
- 恢复遇到原位置同名时停止并提示冲突，不覆盖已有文件。
- 永久删除必须经过 UI 二次确认；清理只处理 `purgeAtEpochMillis <= now` 的条目。

## 测试基线

- JVM：查询规范化、筛选组合、序列化和保留期边界。
- Room：v1→v2 迁移、稳定查询和回收站 DAO。
- Compose：三布局可达、结果一致、筛选与多选语义。
- 真机：file 网关 trash/restore/purge；10k 查询耗时将在专项数据集建立后补录。
