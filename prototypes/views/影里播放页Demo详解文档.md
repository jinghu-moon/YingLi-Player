# 影里播放页 Demo（04-player-demo.html）详解文档

## 0. 文档说明与 Demo 定位

这份 HTML 是一个**浏览器端可交互原型**，用来提前验证「影里」Android 本地视频播放器**播放页**在三种形态下的视觉与交互方案：

- **横屏播放**（16:9，桌面/横屏手机常规播放器）
- **竖屏播放**（9:16，竖屏手机常规播放器）
- **YL 短片**（9:16，抖音式短视频沉浸播放）

页面最外层的品牌头部（Logo + 「横屏 / 竖屏 / YL短片」切换按钮 + 信息按钮）和手机模型外壳（听筒、摄像头孔、状态栏）**只是 Demo 用来并排预览三种形态的展示脚手架，不属于实际 App 的播放页 UI**。实际实现中，三种形态之间的切换应由「旋转手势 / 系统方向感应 / 从视频列表进入短视频流」等真实触发方式驱动，而不是一个常驻的分段开关。真正对应播放页本体的，是 `.player-frame` 及其内部的所有图层。

以下内容按「视觉规范 → 布局结构 → 横竖屏组件与交互 → 短视频模式组件与交互 → 状态动效 → 响应式 → 已知问题」组织，重点覆盖按钮、列表对应的功能与交互逻辑。

---

## 1. 三种播放形态总览

| 形态 | 容器比例 | 圆角 | 核心控制层 | 备注 |
|---|---|---|---|---|
| 横屏 | 16:9 | 外壳 34px / 画面 25px | 顶部栏 + 中央播放键 + 底部（进度行 + 控制行） | 底部控制行左右各有一个可自定义快捷控件槽 |
| 竖屏 | 9:16 | 外壳 45px / 画面 35px | 顶部栏（更紧凑） + 中央播放键（缩小） + 底部悬浮控制条 | 用悬浮胶囊卡片替代横屏的整条底栏，避免遮挡画面 |
| YL 短片 | 9:16 | 同竖屏 | 独立的 `shorts-ui` 整套控件（顶部返回/计数、右侧操作栏、底部信息+进度） | 常规播放器的顶栏/中央键/底栏/竖屏悬浮条在此模式下**全部隐藏**，是完全独立的一套 UI 与手势系统 |

三种形态共用同一个 `<video>` 元素和同一套抽屉/弹窗（设置、播放列表、视频信息、截图、AB 循环），只有短视频模式的「更多」「黑名单」「收藏」是独立的底部面板体系。

## 2. 视觉设计规范

### 2.1 色彩系统

Demo 固定为**深色主题**（`color-scheme: dark`），色板如下：

| Token | 数值 | 用途 |
|---|---|---|

| `--dim` | `#858585` | 更弱的辅助文字（计数、hint） |
| `--line` / `--line-strong` | `#292929` / `#5d5d5d` | 分隔线（弱/强） |
| `--accent` / `--accent-strong` | `#98c3d5` / `#6fa8c0` | 品牌强调色（浅灰蓝），用于进度条已播放段、选中态、播放列表当前项、收藏后的图标高亮基色 |
| `--warning` | `#f7c44d` | 警示色（Demo 中预留，未在此页实际使用） |

| `--player-control-100/70/40` | 白色 100% / 72% / 40% 透明度 | 播放器控件的三级不透明度体系：主图标用 100%，次级/描边用 70%，禁用/轨道底色用 40% |
| `--player-track` | `rgba(255,255,255,.24)` | 进度条未播放段 |
| `--scrim-default` | `rgba(0,0,0,.64)` | 抽屉/弹窗遮罩 |
| `--scrim-strong`（隐式，回退 `rgba(0,0,0,.8)`） | 底部控制栏的渐变遮罩，保证白色图标在亮画面上仍可读 |
| `--radius` | `8px` | 全局默认圆角基准（弹窗、设置项等） |

**设色逻辑要点**：播放器悬浮控件（顶部圆按钮、标题胶囊、快捷槽）统一使用「深色半透明 + 模糊」（`rgb(16 20 18 / .62)` + `backdrop-filter: blur`），而不是直接用 `--surface` 系列，目的是让控件浮在任意画面内容上都保持可读性；这套「毛玻璃深色胶囊」与设置抽屉等「不透明系统色板」是两套并存的视觉语言，分别对应「叠加在视频画面上」和「独立于视频画面」两类场景。

### 2.2 字体排版

- 字体栈：`Inter, "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`（英文优先 Inter，中文回退思源/雅黑，最终回退系统字体）。

- 字号使用密度较高的小字号体系，未使用独立的排版比例文件，按场景实测取值，汇总如下（近似从大到小）：

| 字号 | 场景 |

| 16px | 短视频「更多」面板每一项的主文案 |
| 15px | 短视频标题（`shorts-title`） |
| 14px | 标题胶囊主标题（视频标题） |

| 11px | 品牌副标题、设置选项按钮文字、抽屉说明文字 |

### 2.4 圆角、阴影、模糊、层级

- **圆角体系**：全圆（头像式按钮、开关）、`999px` 胶囊（标题胶囊、快捷开关、AB 点按钮）、`10px`（快捷控件卡片区）、`8px`（`--radius` 基准，弹窗/设置项/控件卡片）、`6–7px`（次级按钮）、大圆角 `25–45px` 专用于设备外壳与播放画面裁切。
- **模糊**：所有「浮在视频画面上」的控件统一 `backdrop-filter: blur(10–12px)`，与「独立面板」（抽屉、弹窗、底部面板）不使用模糊、直接用不透明系统色区分。
- **阴影**：越靠近顶层、越需要与画面区分的浮层，阴影越重——从按钮的 `0 8px 22px rgba(0,0,0,.2)` 到底部面板的 `0 -12px 36px rgba(0,0,0,.42)`、弹窗的 `0 20px 52px rgba(0,0,0,.42)`，均为「向下/向外扩散的深色柔阴影」。
- **层级与浮层管理原则**：Demo 内所有浮层严格分层且**不允许浮层叠浮层**——例如打开设置抽屉/播放列表抽屉时会先关闭截图、AB 胶囊；打开短视频「更多」面板时会先关闭黑名单/收藏面板，反之亦然；关闭任一抽屉的 `closeDrawers()` 也会顺带关闭短视频的所有底部面板。z-index 从底到顶大致为：视频画面(0) → 暗角遮罩(1) → 中央播放键(3) → 顶栏/底栏(4) → 截图预览卡(12)/胶囊(11) → 短视频更多面板遮罩(13)/面板(14)/黑白名单面板(15)/其操作栏(16) → 通用遮罩(8) → 抽屉(9) → 信息弹窗(10) → Toast(30，独立于播放器画面，挂在页面级)。

## 3. 整体布局结构

### 3.1 Demo 外壳（非实际播放器 UI）

- 顶部 64px（≤720px 时 56px）Demo 头部：品牌标（30×30 圆角色块 + 名称 + 副标题）、形态分段开关（横屏/竖屏/YL短片，选中态描边+深底+加粗）、右侧一个信息按钮（仅弹 Toast，无实际作用）。
- 舞台区居中放置一个「手机外壳」：黑色圆角边框 + 摄像头孔 + 侧键装饰；竖屏/短视频形态下额外显示模拟状态栏（时间 + 信号/WiFi/电量图标，纯装饰，无交互）。

### 3.2 播放器画面分层（`.player-frame` 内部，由下到上）

1. `video.player-video` — 主视频画布，`object-fit: contain`（横竖屏默认）。
2. `video.shorts-peek-video` — 短视频模式专用的「相邻视频预加载层」，平时隐藏，仅在切换短视频时参与滑动过渡。
3. 半透明「暗角」遮罩（`::after`，固定 22% 黑）— 常驻，帮助白色控件在明亮画面上保持可读，不随播放状态变化。
4. 顶栏 `.topbar` / 中央键 `.center-controls` / 底栏 `.bottombar`（竖屏为 `.portrait-controls`）— 常规控制层，短视频模式下整组隐藏。
5. 截图胶囊 / AB 胶囊 — 工具模式浮层，二选一显示。
6. 短视频专属 UI（`.shorts-ui`）— 仅短视频模式显示，覆盖顶栏到底栏的全部区域。
7. 通用遮罩 + 抽屉（设置/布局编辑/播放列表）+ 视频信息弹窗 — 最上层的功能性浮层。
8. Toast — 独立于播放器画面，固定在页面底部居中。

### 3.3 三种形态的容器差异

| 维度 | 横屏 | 竖屏 | 短视频 |
|---|---|---|---|
| 顶栏内边距/对齐 | 居中对齐，常规内边距 | 顶部内边距加大（预留状态栏），标题胶囊变窄 | 无常规顶栏，改为短视频专属顶部（返回+计数） |
| 中央播放键 | 70px | 58px，整体下移 20px 避让底部悬浮条 | 无（点击画面任意位置切换播放/暂停） |
| 底部控制 | 完整两行（进度行 + 播放控制行），左右各一组可自定义快捷槽 | 折叠为一张悬浮圆角卡片，播放键与快捷槽同排 | 独立的右侧竖排操作栏 + 底部信息区 + 细进度条 |
| 抽屉呈现方式 | 从右侧滑入（侧边栏） | 从底部滑入（占屏 72% 高的半屏面板），行为切换为「底部弹出式」 | 短视频有自己的一套底部面板（更多/黑名单/收藏），与设置抽屉体系分开 |

## 4. 横屏 / 竖屏播放器 —— 组件与交互详解

### 4.1 顶部栏 `.topbar`

| 元素 | 图标 | 尺寸 | 功能 | 交互逻辑 |
|---|---|---|---|---|
| 返回按钮 | `ti-arrow-left` | 圆形 42×42（竖屏 38×38），字号 21px | 返回媒体库 | 点击仅弹 Toast「返回媒体库」（Demo 占位，实际应触发页面返回） |
| 标题胶囊 | 无 | 最大宽 430px（竖屏 230px），圆角 999px | 展示当前标题 + 元信息 | 纯展示：主标题单行省略，副标题为「本地视频 · 序号/总数」，随 `loadTrack()` 自动更新，不可点击 |
| 右上快捷控件组 | 见 4.5 | 42×42（竖屏 38×38） | 用户自定义的快捷入口（默认：播放列表、音轨、字幕、更多） | 点击触发对应控件的 `runSlotControl()`；竖屏下会自动隐藏「音轨/字幕」两个入口以节省空间 |

### 4.2 中央播放/暂停按钮 `.center-controls`

- 圆形按钮，70px（竖屏 58px），半透明白底 + 深色图标，`hover` 时变全不透明白并轻微放大（`scale(1.04)`）。
- **功能**：播放/暂停切换。
- **交互逻辑**：`video.paused` 时点击 → `play()`；否则 → `pause()`；图标随 `play`/`pause` 事件由 `setPlayingState()` 统一驱动，三处播放键（中央、底部主控、竖屏悬浮条）图标**始终保持同步**。
- 存在一个未挂接实际入口的 `.small` 小尺寸变体（58/48px、半透明更低），预留给「快退/快进」等辅助按钮位，Demo 当前未启用。

### 4.3 底部横屏控制栏 `.bottombar`

分两行：

**进度行 `.seek-row`**
- 左右各一个当前时间/总时长文本（`tabular-nums`，随播放实时刷新）。
- 中间进度条 `<input type="range">`：轨道用 CSS 渐变模拟「已播放段（强调色）/ 未播放段（半透明白）」双色，`--progress` 变量随播放进度动态写入；圆形滑块 14px，白色描边 + 强调色填充。
- **交互**：拖动直接 `seek`（`input` 事件里 `video.currentTime = 拖动值`，若设置了 AB 循环会被夹在 AB 区间内）；播放中会随 `timeupdate` 持续刷新进度与文本。
- 进度条上叠加两个可拖拽的 **AB 点标记**（`.ab-marker`，仅在设置了 A/B 点后显示）：竖线 + 三角指示朝向，通过指针事件独立拖拽调整时间点，也支持键盘方向键微调（一帧步进）。

**控制行 `.control-row`**
- 左侧核心播放组：上一个 / 播放暂停（强调底色，视觉主按钮）/ 下一个，三键横排。
  - 「上一个」：若当前播放超过 5 秒则先回到 0 秒（类似大多数播放器的双重语义）；否则按播放顺序模式切到上一条，列表头部且非循环模式时提示「已经是第一条视频」。
  - 「下一个」：按播放顺序模式（顺序/随机/循环/单曲重复）计算下一条；顺序模式播完最后一条会暂停并提示「播放队列已结束」。
- 中间/右侧两组**可自定义快捷槽**（左组默认：播放顺序、速度、截图、AB 循环；右组默认：画中画、全屏），详见 4.5。

### 4.4 竖屏浮动控制条 `.portrait-controls`

- 竖屏专属，替代横屏的整条底栏：一张圆角浮岛卡片（半透明深底 + 模糊），内部纵向堆叠「播放键 + 快捷槽（单组，最多 6 个，一行横向滚动/挤压）」和「精简进度行」。
- 功能与横屏底栏一致，只是**没有独立的上一个/下一个按钮**（Demo 竖屏形态下这两个动作被收进快捷槽体系，若要保留需通过控件布局把它们加入槽位）。
- 交互逻辑与横屏共享同一套函数（`togglePlayback`、`runSlotControl` 等），只是 DOM 结构更紧凑。

### 4.5 快捷控件系统（核心机制）

这是整个播放页**最重要的可配置交互系统**：顶部右上、底部左下、底部右下（横屏）以及底部悬浮条（竖屏）四个「槽位区」，各自有独立的**数量上限**和**默认控件组合**，用户可在「控件布局」抽屉中自由增删、拖拽排序。

**控件目录**（可被放入任意槽位的全部控件）：

| ID | 名称 | 图标 | 行为类型 |
|---|---|---|---|
| `playlist` | 播放列表 | `ti-list` | 打开播放列表抽屉 |
| `audio` | 音轨 | `ti-music` | 弹 Toast 展示当前音轨（Demo 占位，未做真实切换 UI） |
| `subtitle` | 字幕 | `ti-badge-cc` | 弹 Toast 展示当前字幕（同上，占位） |
| `info` | 视频信息 | `ti-info-circle` | 打开视频信息弹窗 |
| `order` | 播放顺序 | 随状态在四态图标间切换 | 点击循环切换 顺序→随机→列表循环→单曲重复；槽位按钮本身会显示当前模式文字 |
| `speed` | 播放速度 | `ti-gauge` | 点击在 1.0×/1.25×/1.5×/2.0× 间循环，槽位按钮显示当前倍速数值 |
| `screenshot` | 截图 | `ti-camera` | 打开截图工具胶囊 |
| `ab` | A-B 循环 | `ti-repeat` | 打开 AB 循环胶囊 |
| `pip` | 画中画 | `ti-picture-in-picture` | 进入/退出系统画中画，按下态随实际 PiP 状态同步 |
| `rotate` | 旋转屏幕 | `ti-rotate-2` | 在横屏/竖屏形态间切换 |
| `ratio` | 画面比例 | `ti-aspect-ratio` | 点击在 原始/裁剪/拉伸 间循环，直接改写 `video` 的 `object-fit` |
| `lock` | 锁定界面 | `ti-lock` | 弹 Toast 占位，用于「锁定控制栏防误触」 |
| `background` | 后台播放 | `ti-headphones` | 弹 Toast 占位 |
| `sleep` | 睡眠定时 | `ti-alarm` | 弹 Toast 占位（示例值 30 分钟） |
| `more` | 更多 | `ti-dots` | 打开「播放设置」抽屉（承载解码器/顺序/速度/比例/字幕等完整设置项） |
| `fullscreen` | 全屏 | `ti-maximize`/`ti-minimize` | 进入/退出全屏，**始终固定保留、不可移除**（`pinned: true`） |

**默认布局**：

| 槽位区 | 上限 | 默认组合 |
|---|---|---|
| 横屏右上 | 4 | 播放列表、音轨、字幕、更多 |
| 横屏左下 | 4 | 播放顺序、速度、截图、AB 循环 |
| 横屏右下 | 4 | 画中画、全屏 |
| 竖屏底栏 | 6 | 速度、播放顺序、旋转、画中画、全屏、更多 |

**交互逻辑**：
- 每个槽位按钮点击后统一走 `runSlotControl(id)` 分发：有 `toast` 属性的控件只弹提示；有 `action` 属性的按具体动作执行（见上表）。
- 顶部槽位按钮为圆形（跟随顶栏视觉），底部槽位按钮为圆角矩形（跟随控制行视觉），有文字值的控件（顺序、速度）额外带一小段文字标签。
- 播放列表控件按钮固定着色为强调色，作为视觉锚点。

### 4.6 播放设置抽屉 `#settingsDrawer`

从右侧滑入（竖屏形态下改为底部滑入的半屏面板），标题「播放设置」，内容自上而下：

1. **控件布局**（跳转箭头列表项）→ 点击打开「控件布局」抽屉（见 4.7）。
2. **视频信息**（跳转箭头列表项）→ 点击打开视频信息弹窗（见 4.9）。
3. 四组**分段选项**（每组「标签 + 当前值」在上，一排可选按钮在下，选中态描边+着色）：
   - 解码器：HW+ / HW / SW（Demo 中仅做视觉选中和 Toast 提示，未接入真实解码逻辑）
   - 播放顺序：顺序 / 随机 / 列表循环 / 单曲重复（与快捷控件里的「order」双向同步）
   - 播放速度：0.75× / 1.0× / 1.25× / 1.5×（**注意**：与快捷控件「speed」循环的倍速集合 [1, 1.25, 1.5, 2] 不完全一致，见第 8 节）
   - 画面比例：原始 / 裁剪 / 拉伸（**注意**：与快捷控件「ratio」是两套独立状态，见第 8 节）
   - 字幕：简体中文 / 关闭（Demo 占位，未接入真实字幕轨道）
- **交互逻辑**：点击任一选项按钮，同组内互斥高亮，更新组标题旁的「当前值」文字，并弹 Toast「已选择 X」；其中「播放顺序」「播放速度」两组会额外驱动真实的播放行为（`setPlaybackMode` / `video.playbackRate`），其余三组仅做视觉状态记录。

### 4.7 控件布局编辑抽屉 `#controlLayoutDrawer`

- 顶部说明文字 + 「恢复推荐」按钮（一键重置为默认布局）。
- 按四个槽位区分组，每组展示：
  - **已选控件卡片网格**（4 列）：每张卡片可拖拽排序（`draggable`，拖起时半透明+描边提示），左上角小手柄图标标识可拖拽；卡片右下角为**移除按钮**（红色圆形减号），「全屏」卡片因固定保留改为显示一个锁形图标而非移除按钮；已选数量已达槽位上限时该区标题旁会显示「已选数 / 上限」。
  - **可添加控件库**（同样 4 列网格）：展示所有尚未被该槽位使用的控件，点击卡片右下角加号即加入该槽位末尾；若该槽位已达数量上限，库中所有卡片会置灰禁用。
- **交互逻辑**：拖拽只允许在**同一槽位区内**重新排序（跨区拖拽不生效）；任何增删/排序操作都会立即重渲染对应播放器画面上的实际快捷槽（`updateControlLayout()` 同步刷新真实控件区与编辑器本身）。

### 4.8 播放列表抽屉 `#playlistDrawer`

- 标题「播放列表」+ 「当前序号 / 总数」计数。
- 列表项：左侧 72px 宽、16:9 缩略图（用 `<video muted preload="metadata">` 取首帧作为封面），右侧标题 + 时长，当前播放项标题着强调色并在最右侧显示一个强调色播放态小图标。
- **交互逻辑**：点击任意列表项即调用 `loadTrack(index)` 切换到该视频并自动播放，同时抽屉自动关闭；当前项与非当前项的视觉状态（标题着色、指示图标显隐）随切换实时更新。

### 4.9 视频信息弹窗 `#mediaInfoModal`

- 屏幕居中的模态卡片（非抽屉），标题「视频信息」，内容为一个「标签-值」两列列表：文件名、文件位置、封装格式、文件大小、分辨率、画面方向、时长、视频编码、帧率、平均码率、音轨。
- 所有值均从当前 `track` 数据对象和 `video` 元素实时属性（`videoWidth/videoHeight/duration`）计算得出，纯只读展示，无可交互控件。
- 短视频模式下也复用这一弹窗（信息字段改取当前短视频数据，画面方向固定显示「短视频竖屏」）。

### 4.10 截图工具 `#screenshotCapsule`

底部居中悬浮的胶囊工具条，含 4 个按钮：**上一帧**（逐帧后退）、**捕获当前帧**（中间强调色圆角按钮，捕获中会切换为等待态样式）、**下一帧**（逐帧前进）、**关闭**（退出截图模式）。

**交互逻辑**：
- 「上一帧/下一帧」会先 `pause()` 视频，再按当前视频帧率换算的单帧时长精确步进 `currentTime`（避免用固定秒数导致跳帧不精确）。
- 「捕获」触发后会在画面左上角以**从捕获按钮位置飞入**的动画（`scale(2.4)→scale(1)` + 位移）弹出一张**截图预览卡**（116px 宽，16:10，白色描边）；预览卡下沿有一条**3 秒读条**，读条走完后预览卡自动消失。
- 点击预览卡本身会**暂停自动消失倒计时**并在右上角浮出一个**删除按钮**（红色圆形，弹入动画），点击删除按钮立即移除该预览卡；若不点击，3 秒后自动消失，无需用户干预。
- 整个截图动作在 Demo 中直接复用视频海报帧作为「截图结果」，不做真实取帧渲染。

### 4.11 AB 循环工具 `#abCapsule`

底部居中悬浮胶囊，4 个元素：**A 点按钮**（显示「A / 时间或“设置”」）、**B 点按钮**（同上）、**清除**（橡皮擦图标）、**关闭**。

**交互逻辑**：
- 点击 A 点按钮：以当前播放时间设为 A 点；若已有的 B 点早于新 A 点，B 点会被自动清空（保证 A < B 的有效性）。
- 点击 B 点按钮：必须已设置 A 点，且当前时间必须晚于 A 点，否则分别提示「请先设置 A 点」/「B 点必须晚于 A 点」；成功后即刻启用 AB 循环，进度条上的对应区间会被强调色高亮（`--progress-start` 到 `--progress`）。
- AB 循环生效期间，`timeupdate` 监听会在播放到达 B 点时自动把 `currentTime` 跳回 A 点，形成无缝复读；拖动主进度条时也会被自动夹在 [A, B] 区间内。
- 进度条上的 A/B 拖拽标记支持**独立指针拖拽**实时调整时间点（拖动时颜色变为强调色），以及**键盘左右方向键**逐帧微调（用于无鼠标/精细调节场景）。
- 「清除」一键移除 A、B 点并回到自由进度模式。

### 4.12 全屏与画中画

- **全屏**：优先使用标准 Fullscreen API 对 `.player-frame` 请求全屏，回退到 iOS 的 `webkitEnterFullscreen`；不支持时弹 Toast 提示。图标随 `fullscreenchange` 事件在 `ti-maximize`/`ti-minimize` 间实时互换，所有引用该动作的按钮（无论在哪个槽位）图标同步更新。进入全屏且当前是竖屏/横屏形态时，会尝试调用 `screen.orientation.lock()` 匹配当前形态的方向锁定（失败时静默降级，不打断体验）。
- **画中画**：优先标准 `requestPictureInPicture`，回退 Safari 的 `webkitSetPresentationMode`；按钮的按下态（`aria-pressed`）随 `enterpictureinpicture`/`leavepictureinpicture` 事件同步，让「画中画」这个开关型控件在任意槽位都能正确反映当前状态。

### 4.13 形态切换 / 旋转

- 快捷控件「旋转屏幕」与设置抽屉外的 Demo 顶部分段开关本质调用同一个函数：在横屏与竖屏之间切换容器类名、栏位显隐、槽位挂载点，并复位截图/AB 等浮层。
- 从短视频模式切回横竖屏时会重新加载常规播放列表中的当前视频（保留原播放位置由 Demo 简化处理为重新起播，实际实现建议保留播放进度）。

### 4.14 Toast 提示

- 页面级固定在底部居中的深色圆角提示条，1.7 秒后自动淡出滑走；用于几乎所有「Demo 占位」动作（返回、后台播放、睡眠定时等尚未实现真实效果的按钮）以及真实状态变化的确认反馈（切换速度、设置 AB 点、收藏/屏蔽短视频等）。同一时刻只保留一条提示，新提示会打断并替换旧的计时器。

## 5. 短视频模式（YL 短片）—— 组件与交互详解

进入短视频模式后，常规播放器的顶栏/中央键/底栏/竖屏悬浮条**整组隐藏**，替换为完全独立的 `.shorts-ui` 界面，交互模型也从「点按钮为主」切换为「手势为主、按钮为辅」。

### 5.1 顶部与右侧操作栏

**顶部** `.shorts-top`：左侧返回按钮（`ti-arrow-left`，36×36 圆形）+ 右侧「当前序号 / 总数」计数胶囊，均为纯展示/单一返回动作，点击返回即调用 `setViewMode('portrait')` 回到竖屏常规播放器。

**右侧竖排操作栏** `.shorts-rail`（贴右边缘，纵向 3 个）：

| 按钮 | 图标（默认→激活） | 功能 | 交互逻辑 |
|---|---|---|---|
| 收藏 | `ti-star` → `ti-star-filled`（激活时图标变粉红 `#ff9eb1`） | 收藏/取消收藏当前短视频 | 点击切换收藏集合（内存态 `Set`），文字标签随之显示「收藏/已收藏」，若收藏列表面板正开着会联动刷新 |
| 屏蔽 | `ti-ban` | 加入/移出黑名单 | 同上逻辑，切换黑名单集合，联动黑名单面板刷新 |
| 更多 | `ti-dots` | 打开「更多」底部面板 | 见 5.4 |

每个按钮为「48px 圆形图标 + 下方 10px 文字标签」的竖排组合，hover/激活时图标底色变亮并轻微放大（`scale(1.06)`）。

### 5.2 底部信息区与进度条

- **信息区** `.shorts-bottom`（贴左下，右侧预留给操作栏）：标题（单行省略）、简介文案（单行省略）、一排标签 chip（分辨率、文件大小、当前时间/总时长），文字均带阴影以保证在任意画面上可读。
- **进度条** `.shorts-seek`：贴底部的极细（3px）进度条，无左右时间文本（时间信息已并入上方标签区），拖动逻辑与常规进度条一致但样式更轻量。

### 5.3 手势系统详解

短视频模式的**核心交互不是按钮，而是覆盖整个画面的指针手势**，逻辑如下（均基于 `pointerdown/move/up`）：

| 手势 | 触发条件 | 效果 |
|---|---|---|
| **单击画面** | 点击非按钮/输入区域 | 播放 / 暂停切换（与常规模式的中央键语义一致，只是没有可见按钮） |
| **上滑** | 垂直位移超过阈值（约 6px 起判定方向，实际切换以内部状态机为准）且未触发左右轴 | 切换到**下一条**短视频：先预加载下一条到隐藏的「预览层」，画面随手指位移实时跟随平移，松手时按位移是否超过 **64px** 提交阈值，决定「继续完成切换（0.32s 缓动滑动过渡）」还是「回弹留在当前视频」 |
| **下滑** | 同上，方向相反 | 切换到**上一条**短视频，过渡逻辑相同 |
| **左右滑动** | 横向位移判定为主轴，松手时位移绝对值 ≥ **42px** | 快退 / 快进 **5 秒**（右滑快退、左滑快进），并弹 Toast 提示秒数 |
| **长按（约 360ms）** | 按住不放且未触发明显位移 | 临时以 **2.0× 倍速**播放（用于快速预览剧情），松手后若未手动锁定倍速则自动恢复 1.0× |
| **键盘 ↑ / ↓（无障碍/桌面）** | — | 等效于下滑/上滑，切上一条/下一条 |

补充说明：
- 上下滑动与左右滑动**互斥判定**——一旦确定是左右轴手势，就不再触发切换视频的逐帧位移；判定前的微小位移（<10px）不做方向锁定，避免误触。
- 视频切换用了「相邻视频预加载 + 双层平移」的实现方式：当前视频层与下一条的预览层同时存在并跟随手指位移，只有松手提交后才真正调用 `loadShortTrack()` 加载新的数据源，保证过渡观感连贯不黑屏。
- **自动连播**（播放结束事件）：若开启了「循环当前视频」则原地重播；否则若「自动切换下一条」开启，则自动执行与上滑等价的切换动画。

### 5.4 更多面板 `#shortsMoreSheet`

从底部滑入的圆角面板（顶部有一条「拖拽手柄」装饰条，暗示可下滑关闭），列表项自上而下：

| 列表项 | 图标 | 类型 | 交互逻辑 |
|---|---|---|---|
| 自动切换下一条短视频 | `ti-player-track-next` | 开关（Switch） | 切换 `shortsAutoNext` 状态，胶囊开关随之滑动着色 |
| 长按倍速 | `ti-gauge` | 按钮 + 数值展示 | 短按：在 1.0×/2.0× 间切换**锁定**倍速；长按（约 320ms）：临时预览 2.0×，松开若未锁定则回落 1.0×（与手势系统里画面上的长按共享同一套倍速状态，但入口是显式按钮，方便不便手势操作的场景） |
| 分享 | `ti-share-3` | 按钮 | 关闭面板并弹 Toast 占位 |
| 收藏列表 | `ti-star` | 跳转 | 打开「收藏视频」面板（5.5） |
| 循环当前视频 | `ti-repeat-once` | 开关（Switch） | 切换 `shortsRepeatCurrent`，开启后播放结束会原地重播而不是自动下一条 |
| 画中画 | `ti-picture-in-picture` | 按钮 | 关闭面板并触发画中画（复用 4.12 逻辑） |
| 截图 | `ti-camera` | 按钮 | 关闭面板并打开截图工具（复用 4.10 逻辑） |
| 画面比例 | `ti-aspect-ratio` | 按钮 + 数值展示 | 点击在 裁剪/原始/拉伸 间循环，直接改写短视频画面的 `object-fit`（**独立于**常规模式的画面比例状态，见第 8 节） |
| 视频信息 | `ti-info-circle-filled` | 跳转 | 打开视频信息弹窗（数据取当前短视频） |
| 黑名单视频管理 | `ti-ban` | 跳转 | 打开「黑名单视频」面板（5.5） |
| 删除短视频 | `ti-trash` | 按钮（危险态：文字/图标全部着 `--error` 色） | Demo 中仅关闭面板并提示「删除短视频为交互演示，未修改本地文件」，真实实现需接入永久删除确认流程 |

每一行是「44px 图标区 + 主副文案 + 右侧数值/开关」的固定网格结构，保证不同类型的行（纯按钮/开关/带数值）视觉对齐一致。

### 5.5 黑名单管理 / 收藏列表面板

两个结构相同的底部面板（黑名单 `#shortsBlacklistSheet` / 收藏 `#shortsFavoritesSheet`）：

- 标题 + 「条数」计数 + 关闭按钮。
- 列表区：每行「文件类型图标 + 文件名（单行省略）+ 移除按钮」；黑名单行图标为 `ti-file-video`，收藏行图标为实心星标 `ti-star-filled`。
- **空状态**：列表为空时显示居中的灰色提示文字（「暂无黑名单视频」/「暂无收藏视频」），不显示空列表容器边框。
- **交互逻辑**：点击某行的移除按钮即从对应集合中删除该文件名并重渲染列表、刷新计数，同时同步更新短视频操作栏上对应按钮（收藏/屏蔽）的高亮状态——即这两个面板与右侧操作栏按钮是**双向绑定**的同一份数据。

### 5.6 首次进入手势提示

- 首次切入短视频模式时，画面中央会短暂浮现一段半透明提示卡片：「上滑下一条 · 下滑上一条 / 左右滑动快进或快退 · 长按 2.0x」，2.8 秒后自动淡出，且整个会话只出现一次（`shortsHintShown` 标记位）。

## 7. 响应式适配

- **≤720px**：Demo 头部收窄到 56px，隐藏品牌副标题与信息按钮；横屏播放器容器改为几乎撑满视口宽度；底部控制行按钮整体缩小（图标从 20px 降到 17px），且「带文字标签」的控件在此宽度下**只保留图标、隐藏文字**，为槽位省出空间；页面右下角的操作提示文字隐藏。
- **≤480px**：品牌名字号进一步缩小，分段开关按钮更窄。
- **竖屏/短视频容器**始终以「视口高度」为约束反推宽度（`(100vh − 128px) × 9/16`），保证在任意窗口高度下都不会超出可视区域；横屏容器同理以「宽度」和「高度换算宽度」取更小值，保证 16:9 完整可见。
- 抽屉在**横屏**下是从右侧滑入的侧栏（固定宽度，最大占屏 84%）；切到**竖屏形态**后，同一套抽屉组件会**改变呈现方式**为从底部滑入、占屏最高 72% 的半屏面板——这是同一 DOM/同一套开合逻辑在不同容器类名下的样式重写，而不是两套独立组件。

## 8. 使用本文档时的注意事项（Demo 已知局限 / 建议在正式实现前统一）

以下几点是通读源码后发现的**Demo 自身的不一致或占位逻辑**，正式实现 Kotlin/Compose 版本时建议提前拍板，避免把 Demo 的“临时实现”误当作最终设计意图带入正式产品：

1. **播放速度存在两套独立状态**：「播放设置」抽屉里的速度选项集合是 `0.75×/1.0×/1.25×/1.5×`，而快捷控件「speed」循环点击的集合是 `1×/1.25×/1.5×/2.0×`，两者不完全重合、也未做双向同步（点其中一处，另一处的高亮不会联动更新）。
2. **画面比例存在三套独立状态**：常规模式的「设置抽屉画面比例」、常规模式快捷控件「ratio」（直接改 `video.style.objectFit`）、短视频模式「更多面板」里的画面比例，三者各自维护自己的索引与显示值，互不同步。
3. **解码器、字幕两组设置项是纯视觉占位**：点击只做选中态切换 + Toast 提示，没有接入任何真实的解码器切换或字幕轨道加载逻辑。
4. **「删除短视频」「后台播放」「睡眠定时」「锁定界面」等按钮均为 Toast 占位**，未实现真实功能，正式实现时需要各自补上真实的确认流程/持久化逻辑。
5. **黑名单/收藏/自动连播/循环当前视频等短视频状态均为纯内存态**（页面刷新即丢失），且黑名单初始预置了一条示例数据，均为 Demo 演示所需，非产品默认值。
6. **播放列表当前仅有 2 条常规视频、3 条短视频**样例数据，缩略图直接取视频首帧，仅用于验证列表交互，不代表真实素材来源（真实场景应来自本地媒体库索引）。

除以上几点外，本文档第 2–7 节所述的颜色、字体、图标、尺寸、布局结构与交互逻辑均可作为正式实现的直接参考依据。
