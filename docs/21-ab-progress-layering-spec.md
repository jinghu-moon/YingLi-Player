## 2. 剖面图的读法与 demo 内部的自洽性

### 2.1 2.4 倍换算法

剖面图 `class="anat" viewBox="0 0 920 350"`（`demo.html:271`），`sec-lead` 自述"同一套几何放大 **2.4 倍**（右侧标注为真实 dp 值）"（`demo.html:269`）。换算：**dp = 该几何的像素跨度 ÷ 2.4**。

算例（用来验证这条换算）：

| 几何（SVG 单位） | 像素跨度 | ÷2.4 | 右侧标注 | 出处 |
|---|---|---|---|---|
| 徽标 `rect y=179..209` | 30 | **12.5** | `12.5dp` | `demo.html:289`、`:319` |
| 徽标→循环层 `y=209..221` | 12 | **5** | `5dp` | `demo.html:313`、`:320` |
| 循环层 `y=221..228` | 7 | **≈2.9** | `3dp` | `demo.html:294`、`:321` |
| 循环层→轨道层 `y=228..250` | 22 | **≈9.2** | `9dp` | `demo.html:315`、`:322` |
| 轨道层 `y=250..260` | 10 | **≈4.2** | `4dp` | `demo.html:298`、`:323` |

→ 右侧标注是**取整后的 dp**；`5dp` 那一档标注的是"徽标下沿到循环层上沿"的**间距**，**不是**区间条厚度（区间条厚度是下面那一档 `3dp`）。**这条纠正很重要**：把 `5dp` 读成"区间条 5dp 厚"是误读。

### 2.2 竖直方向的"分寸链"（从下往上）

```
刻度行        y≈296..308      （文字基线 298）
  ↑ 4dp 间距   （右侧标注 4dp 在这里是"轨道层→刻度行"的间距 y=260..?）
轨道层        y=250..260      4dp
  ↑ 9dp 间距
循环层        y=221..228      3dp（竖线 y=221..250，跨 29px ≈ 12dp）
  ↑ 5dp 间距
徽标层        y=179..209      12.5dp
浮签层        y=136..168      12.5dp（虚线幽灵框，仅拖动时出现）
```

合计：`12.5 + 5 + 3 + 9 + 4 = 33.5dp`（从徽标上沿到刻度行基线附近），与"标记组总高约 30dp"是同一量级 —— 但 demo **没有**给出 `30dp` 的加总式。**demo 未指定（待定）**。

### 2.3 两处 demo 内部不自洽（记录，不当成规格）

1. **区间条厚度**：右侧标注 `5dp`（`demo.html:321`）与几何 `7px`（`:294`，÷2.4 ≈ `2.9dp`）不一致；不过按 §2.1 的读法，`5dp` 其实标注的是"徽标→循环层"的间距，**真正**的区间条厚度标注是 `3dp`（`:321` 的第三行），与几何 `7px` ≈ `2.9dp` 基本吻合（取整误差）。→ 结论：**区间条厚度 = 3dp（剖面口径）**。
2. **"未激活 28%" vs "休眠 50%"**：
   - `demo.html:329` 的注脚写"区间条 · 激活 100% / **未激活 28%**"；
   - JS 里 `opacity=".28"` **只**出现在"仅 A"那一支（`demo.html:452`），而 `<g opacity="${dim?.55:1}">`（`:479`）里的 `.55` 是"区间完整 + 非编辑 + 非拖动"时的**整组**透明度，注释写作"会话休眠：整体 50%"（`:434`）。
   - → **demo 未指定（待定）**：注脚里的"未激活 28%"到底指"仅 A 的预判区间条"（JS 事实），还是指"编辑会话休眠时的标记组"（`.55` 那一支）。两处数值不同（28% / 55%），**不能合并**。

### 2.4 两套坐标系不可互换

- 剖面图：`viewBox="0 0 920 350"`，2.4 倍，右侧标注是 dp。
- 真机原型：`#ptrack` = `viewBox="0 0 300 96"`（`demo.html:180`），JS 用 `W=300, pad=10, tw=280, ty=58`（`:429`）画。里面的 `12.5`（徽标）、`4`（轨道厚）、`48`（夸大最小宽度）都是**这套坐标的像素**。
- **demo 未指定（待定）**：`#ptrack` 的 300×96 与真机 dp 的关系（`.phone` 宽 `328px`、`#ptrack` 宽 100%，`demo.html:53`、`:70`）。→ 因此**不能**把 `#ptrack` 里的 `12.5` 当成 `12.5dp`、把 `48` 当成 `48dp`。
