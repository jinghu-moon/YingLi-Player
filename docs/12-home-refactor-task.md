# 首页重构任务

## 1. 文档目的

本任务以 [`prototypes/views/01-home-demo.html`](../prototypes/views/01-home-demo.html) 为首页视觉和交互事实源，重构 Android Compose 首页，使其符合影里的产品定位：

> 观看为主，整理为辅；本地优先、无账号、无行为遥测。

本任务覆盖首页布局、首页数据查询、卡片可见性、卡片排序、统计摘要、合集入口和维护提醒。它不是简单的 UI 换肤，也不是把 HTML/CSS 逐行翻译为 Compose。

项目处于开发阶段，不考虑旧首页 API、旧状态结构或旧持久化格式的兼容性。允许删除 `HomeViewModel` 中不合理的全量内存派生逻辑，直接替换为新的首页状态和查询接口；但必须通过前后测试确认当前权限、扫描、播放、搜索、目录和整理功能没有被无意破坏。

## 2. 事实源与取舍

### 2.1 原型事实源

HTML Demo 固定了以下产品行为：

- 默认浅色模式，暂不引入深色模式和动态配色。
- 首页运行在手机外壳的独立内容视口内，顶部栏和底部导航固定，内容区域独立滚动。
- 顶部栏左侧显示五线光栅 Logo、“影里”和媒体源扫描状态。
- 顶部栏右侧只显示搜索按钮和更多按钮。
- 更多菜单提供“添加媒体目录”“重新扫描”“自定义首页”“设置”。
- 底部导航固定为“首页 / 视频 / 整理”三项，设置不进入一级导航。
- 首页的每个业务区块是独立卡片，卡片之间使用统一间距，不使用卡片嵌套卡片。
- 统计卡片右上角有进入统计页面的箭头。
- 首页不在统计卡片下方重复放置“添加目录”和“重新扫描”按钮。
- 搜索按钮点击后在顶部栏下展开搜索输入框，仅匹配本地内容。
- “自定义首页”使用 Bottom Sheet，不跳转独立页面。

### 2.2 默认卡片顺序

当前 Demo 的默认顺序为：

```text
统计卡片
继续观看
最近添加
我的合集
常用文件夹
需要处理
```

该顺序是本次实现基线。排序编辑器允许用户改变顺序；产品后续若决定采用“观看优先”的默认顺序，应修改默认配置和验收测试，不在实现中偷偷使用另一套顺序。

### 2.3 空状态和条件显示

空模块不显示空壳卡片，也不渲染 Demo 假数据：

- 没有可继续观看的视频时隐藏“继续观看”。
- 没有最近添加的视频时隐藏“最近添加”。
- 没有合集时隐藏“我的合集”。
- 没有常用文件夹时隐藏“常用文件夹”。
- 没有重复、回收站或转码事项时隐藏“需要处理”。
- 统计卡片只要媒体库存在就显示；没有媒体数据时显示明确的空状态或进入媒体授权流程。

条件卡片隐藏时不得从用户保存的排序配置中删除。数据重新出现后，恢复其原来的排序位置。

## 3. 当前实现问题

当前实现位于：

- `app/src/main/java/seeyuer/yingli/player/feature/home/HomeViewModel.kt`
- `app/src/main/java/seeyuer/yingli/player/feature/home/HomeScreen.kt`
- `app/src/main/java/seeyuer/yingli/player/app/MainActivity.kt`
- `app/src/main/java/seeyuer/yingli/player/app/library/RoomLibraryRepositories.kt`
- `app/src/main/java/seeyuer/yingli/player/app/organize/RoomOrganizeRepositories.kt`

已确认的问题：

1. `HomeViewModel` 以 `LibraryQuery(pageSize = 200)` 读取一批媒体，再在内存中计算继续观看、最近添加、常用文件夹、总时长和已看比例；首页摘要不应依赖固定的 200 条样本。
2. `HomeScreen` 使用固定的 `if` 顺序渲染区块，无法支持用户排序和隐藏。
3. 当前首页统计区块仍包含总时长、已看比例和重复的目录操作，与最新 Demo 的统计卡片契约不一致。
4. 当前收藏/合集没有首页投影；合集数据已经存在整理域，需要通过稳定的 ID 和摘要模型接入首页。
5. 当前没有“需要处理”聚合模型；重复文件、回收站、转码建议不能由 UI 拼接伪数据。
6. 当前没有首页布局配置的持久化接口，也没有 Bottom Sheet 排序编辑器。
7. 当前首页的图片请求虽然有版本相关 key，但首页媒体项仍直接依赖 Coil `AsyncImage`；缩略图重构应遵循 `docs/11-compose-thumbnail-prefetch-plan.md` 的 `ThumbnailLoader` 边界，不在本任务中重新发明第二套缩略图协议。

## 4. 目标信息架构

### 4.1 顶部栏

```text
五线光栅 Logo   影里
                3 个目录 · 12 分钟前扫描       搜索  更多
```

要求：

- Header 固定在首页内容视口顶部，不随内容滚动。
- 扫描状态由媒体索引状态驱动：空闲、扫描中、部分失败、完成。
- 扫描中显示轻量进度线和状态文字，不阻塞已经可见的首页内容。
- 搜索按钮触发展开/收起；搜索输入框有界、有清除按钮和无障碍标签。
- 更多菜单使用固定浅色组件 Token，菜单项为图标 + 文字。
- “设置”仅位于更多菜单，不增加底部第四项。

### 4.2 统计卡片

统计卡片是一个独立卡片，结构如下：

```text
┌──────────────────────────────┐
│ 媒体概览                 >   │
├──────────────┬───────────────┤
│ 8,247        │ 1.8TB         │
│ 视频         │ 占用空间      │
├──────────────────────────────┤
│ 设备存储              2.3/3.0TB│
│ ████████████░░░░░░░░░░        │
│ ● 视频60% ● 其他16% ● 可用24% │
└──────────────────────────────┘
```

契约：

- 顶部只显示“视频”和“占用空间”两项指标。
- 不在首页显示总时长和已看比例；这些数据属于未来统计详情页。
- “占用空间”指影里媒体库内视频总大小。
- “设备存储”指设备整体存储使用情况，不能与媒体库占用混为一谈。
- 容量单位使用紧凑格式：`1.8TB`、`2.3/3.0TB`，不混用空格。
- 存储条使用视频 60%、其他 16%、可用 24% 的示例结构；生产数据必须来自存储能力接口。
- 三个图例均有色点，颜色仅表达存储组成，不承担成功、错误或观看进度语义。
- 右上角箭头是唯一进入统计详情页的入口，点击后导航到未来的统计页面。
- 卡片本身当前不作为整体可点击区域，避免制造尚未实现的清理入口。

### 4.3 继续观看卡片

- 条件显示，仅展示符合 `ContinueWatchingPolicy` 的项目。
- 采用横向滚动媒体卡片，卡片使用固定 16:9 缩略图。
- 显示标题、已播放/总时长、百分比和进度条。
- 点击卡片进入播放页并恢复对应媒体。
- 继续观看查询按最后播放时间降序并在数据库层限制数量，不扫描全部媒体后再内存过滤。
- 缩略图请求使用统一的 `ThumbnailRequest`，预取和显示请求必须完全一致。

### 4.4 最近添加卡片

- 条件显示，按媒体修改/加入索引时间降序。
- 使用横向缩略图列表，固定 16:9，显示时长胶囊、文件名、体积和分辨率。
- 默认只取首页所需数量，不能为了首页读取整个媒体库。
- 点击媒体进入播放页；“视频库”入口进入视频界面并保留来源。
- 失败缩略图显示统一占位，不阻塞横向列表滚动。

### 4.5 我的合集卡片

- 条件显示，没有合集时不占位。
- 展示最近使用或最近更新的 2～3 个合集，并保留“全部”入口。
- 每个合集只保存并传递稳定的 `collectionId`，不能把媒体对象列表序列化到导航参数。
- 合集封面由合集内媒体缩略图组成；无可用缩略图时使用中性占位。
- 显示合集名称和视频数量，名称遵循整理域长度限制。
- 点击进入合集详情或整理页对应合集，不直接修改媒体文件。
- 合集数据来自 `CollectionRepository`/整理域，不在 `HomeViewModel` 内复制 Room 聚合逻辑。

### 4.6 常用文件夹卡片

- 条件显示，展示访问频率或视频数量最高的目录别名。
- 每行包含文件夹图标、名称、视频数量/体积摘要和进入箭头。
- 目录行不复制媒体实体；点击只传递稳定的目录/来源标识。
- 聚合查询在数据库层完成，数量固定，避免按首页请求加载全部媒体。
- 文件夹为空、来源失效或权限撤销时，该行应消失或显示明确的离线状态，不显示过期的伪数据。

### 4.7 需要处理卡片

- 条件卡片，有待处理事项才显示。
- 当前支持三类入口：重复视频、回收站即将清空、旧编码视频转码建议。
- 每行包含中性图标、标题、摘要和进入箭头；危险操作的红色只在实际危险动作确认界面使用。
- 重复视频示例：`12 组 · 可释放约 2.1GB`。
- 回收站示例：`6 个视频 · 3 天后自动清空`。
- 转码示例：`23 个 · 转码可能节省空间`。
- 生产实现必须由各自领域状态驱动，不能把 Demo 文案直接写入产品状态。
- 查重、回收站、转码尚未有可用数据时，整张卡片隐藏；不显示“即将支持”伪入口。
- 保险箱不作为普通维护提醒。只有存在需要用户确认的安全状态时，才由安全域提供单独状态入口。

## 5. 首页卡片配置模型

### 5.1 稳定 ID

定义首页专用稳定 ID，不使用展示文案作为 key：

```kotlin
enum class HomeCardId {
    STATS,
    CONTINUE_WATCHING,
    RECENTLY_ADDED,
    MY_COLLECTIONS,
    FREQUENT_FOLDERS,
    MAINTENANCE,
}
```

### 5.2 配置模型

```kotlin
data class HomeCardPreference(
    val id: HomeCardId,
    val visible: Boolean,
)

data class HomeCardLayout(
    val order: List<HomeCardId>,
    val hidden: Set<HomeCardId>,
)
```

约束：

- `order` 必须包含每个已知卡片一次，不能重复。
- 未知 ID、重复 ID 和损坏数据在读取时被丢弃，并按默认顺序补齐。
- `hidden` 只影响用户偏好，不代表业务数据为空。
- 条件卡片的业务空状态和用户隐藏状态分别计算：`visibleByData && visibleByPreference`。
- 用户隐藏卡片后，首页不显示；重新打开编辑器时仍可看到该卡片并可恢复显示。
- 统计卡片允许隐藏，但默认显示。
- 至少保留一个可见卡片；若用户隐藏全部卡片，首页显示“已隐藏所有模块”的恢复提示，不让内容视口永久空白。

### 5.3 持久化

新增稳定的 `HomeLayoutRepository`，底层使用 DataStore Preferences 或项目现有偏好存储方式：

```text
home_card_order_v1
home_card_hidden_v1
```

开发期不增加旧格式迁移或兼容分支。若现有开发数据格式与新模型冲突，直接按默认值重建首页布局配置。

持久化要求：

- 进程重建后顺序和隐藏状态保持。
- 读取失败或值非法时安全回退默认布局，并记录脱敏诊断。
- 保存操作不阻塞首页首屏渲染。
- 不保存媒体对象、URI、标题、路径或缩略图，只保存卡片 ID 和布局偏好。

## 6. 自定义首页 Bottom Sheet

### 6.1 入口和生命周期

- 顶部更多菜单增加“自定义首页”。
- 点击后打开 `ModalBottomSheet`，不跳转独立页面。
- Bottom Sheet 高度约为屏幕 80%～88%，内部排序列表独立滚动。
- 打开编辑器时读取当前布局快照；点击“完成”保存并关闭。
- 点击遮罩或关闭按钮时，采用即时保存策略：已经完成的排序/隐藏操作保留。
- 点击“恢复默认”只重置排序和隐藏状态，不关闭弹窗。
- 目录选择 Bottom Sheet 和首页编辑 Bottom Sheet 不能同时打开。

### 6.2 排序列表

每行显示：

```text
卡片图标   卡片名称        显示/隐藏   拖拽手柄
```

交互要求：

- 拖拽只从手柄开始，避免点击卡片摘要时误触发排序。
- 长按或按下手柄后进入拖拽态，拖拽行增加阴影并轻微缩放。
- 列表接近顶部/底部时支持自动滚动。
- 拖拽期间不触发首页卡片的播放、导航或维护操作。
- 拖拽结束后立即更新内存布局，并在完成或变更时持久化。
- Bottom Sheet 普通状态允许下拉关闭；拖拽期间暂时禁用 sheet 关闭手势或将其交给排序手势。
- 排序列表使用稳定 key：`HomeCardId`。

### 6.3 隐藏控制

- 使用眼睛/关闭眼睛图标按钮表示当前可见状态。
- 每个按钮有“显示统计卡片”“隐藏统计卡片”等完整无障碍标签。
- 隐藏状态同时通过图标和降低透明度表达，不只依赖颜色。
- 业务数据为空导致的自动隐藏，不改变编辑器中保存的用户可见性偏好。
- 重新显示卡片后恢复其原排序位置。

### 6.4 无障碍替代操作

拖拽不是唯一排序方式。拖拽手柄必须支持：

- 键盘/辅助设备方向键上移、下移；
- 可被 TalkBack 识别的“上移”“下移”动作，或等价的可访问自定义动作；
- 显示/隐藏按钮的状态朗读；
- Bottom Sheet 标题、关闭、完成、恢复默认均有语义标签。

## 7. 数据和领域重构

### 7.1 首页状态不再持有全量媒体列表

删除当前 `HomeViewModel` 通过 `LibraryQuery(pageSize = 200)` 构造首页摘要的方式。首页只持有各卡片需要的有限投影：

```kotlin
data class HomeUiState(
    val scanState: HomeScanState,
    val layout: HomeCardLayout,
    val stats: HomeStats?,
    val continueWatching: List<HomeMediaPreview>,
    val recentlyAdded: List<HomeMediaPreview>,
    val collections: List<HomeCollectionPreview>,
    val frequentFolders: List<HomeFolderPreview>,
    val maintenance: List<MaintenanceItem>,
    val search: HomeSearchState,
)
```

UI 根据 `layout.order` 渲染卡片，并对每个卡片再次应用数据条件和用户隐藏状态：

```text
保存顺序
    ↓
按顺序取得卡片定义
    ↓
过滤用户隐藏
    ↓
过滤业务空模块
    ↓
渲染有限投影
```

### 7.2 查询边界

新增或扩展稳定的首页查询接口，建议按卡片拆分：

- `observeHomeStats()`：视频数量、媒体总大小、设备存储摘要。
- `observeContinueWatching(limit)`：根据播放历史和继续观看策略在数据库/Repository 层限制结果。
- `observeRecentlyAdded(limit)`：按索引时间或修改时间排序并限制结果。
- `observeHomeCollections(limit)`：按合集更新时间返回 ID、名称、数量和封面候选。
- `observeFrequentFolders(limit)`：数据库聚合目录数量和体积。
- `observeMaintenanceItems()`：合并查重、回收站、转码状态；无事项返回空列表。

不得为了复用一个“全量媒体 Flow”而再次将 8000+ 条媒体加载到 `HomeViewModel`。首页统计必须使用 SQL `COUNT`/`SUM` 或等价聚合；列表卡片必须使用 `LIMIT`；目录聚合必须在数据库执行。

### 7.3 搜索

- 搜索仅匹配本地视频名称、文件夹别名、合集名称和标签。
- 搜索条件变化使用 `debounce + flatMapLatest`，旧查询必须取消。
- 搜索结果使用独立有限列表或 Paging，不复用首页所有卡片的内存列表。
- 搜索展开时不改变用户保存的卡片顺序和隐藏状态。
- 清空搜索后恢复首页卡片布局和滚动位置。

### 7.4 扫描状态

- 首页观察 `MediaLibraryViewModel` 或统一媒体索引状态，不复制扫描状态机。
- 扫描中继续显示已经发现的首页数据；不得用全屏加载遮住已有内容。
- 重新扫描由顶部更多菜单触发，完成后刷新对应查询 Flow。
- 目录添加由顶部更多菜单打开已有授权流程。
- 扫描失败、权限撤销、来源离线必须转换为已有统一失败/提示模型，不在首页硬编码异常文案。

## 8. Compose 实现边界

### 8.1 组件拆分

建议拆分为以下组件，名称可按现有设计系统调整：

- `HomeRoute`
- `HomeTopBar`
- `HomeSearchPanel`
- `HomeMoreMenu`
- `HomeCardHost`
- `HomeStatsCard`
- `ContinueWatchingCard`
- `RecentlyAddedCard`
- `MyCollectionsCard`
- `FrequentFoldersCard`
- `MaintenanceCard`
- `HomeCardOrderSheet`
- `HomeCardOrderRow`

每个业务卡片只负责展示自己的稳定 UI 状态和事件，不直接访问 DAO、DataStore、MediaStore 或 Activity Result。

### 8.2 卡片排序渲染

不要用六个独立的 `if` 语句固定顺序。使用卡片 ID 到渲染函数的集中映射：

```kotlin
val cardRenderers: Map<HomeCardId, @Composable () -> Unit> = mapOf(
    HomeCardId.STATS to { HomeStatsCard(...) },
    HomeCardId.CONTINUE_WATCHING to { ContinueWatchingCard(...) },
    HomeCardId.RECENTLY_ADDED to { RecentlyAddedCard(...) },
    HomeCardId.MY_COLLECTIONS to { MyCollectionsCard(...) },
    HomeCardId.FREQUENT_FOLDERS to { FrequentFoldersCard(...) },
    HomeCardId.MAINTENANCE to { MaintenanceCard(...) },
)
```

实际实现可以采用 `when` 以获得更强的类型检查，但必须由 `layout.order` 驱动顺序，而不是通过 UI 代码顺序隐式定义。

### 8.3 固定尺寸和缩略图

- 首页横向媒体卡片固定 16:9 比例和稳定宽度。
- 不使用无界宽高让图片加载器退化为原图尺寸。
- 所有首页缩略图使用统一的 `ThumbnailRequest`、版本 key、目标尺寸和占位策略。
- 遵循 `docs/11-compose-thumbnail-prefetch-plan.md`：UI 不直接暴露 Glide/Coil 请求类型，预取与显示请求使用同一构造规则。
- 首页横向列表的预取数量以真实设备基准为依据，不凭感觉扩大缓存窗口。
- `CacheWindow`、Paging 页面缓存和缩略图缓存分别调参、分别测试。

### 8.4 颜色和组件

- 默认固定浅色主题，使用 `02-color-system-components.html` 的浅色语义 Token。
- 不使用 Material 动态配色。
- 业务组件不直接使用 Hex 或 Primitive Token。
- 结构选中使用中性黑白反转；钢蓝仅用于链接、焦点、信息和处理中。
- 不用绿色表示观看进度，不用红色装饰普通卡片。
- 卡片圆角保持 8dp 或设计系统规定的紧凑圆角。
- 触控目标至少 48dp；图标按钮必须有 tooltip/contentDescription。
- 页面区块不使用装饰性光斑、背景 orb 或单色渐变。

## 12. 完成定义

只有同时满足以下条件，首页重构才算完成：

1. 所有 Demo 中冻结的首页结构和交互已在 Compose 中实现，或记录了明确的产品取舍。
2. 首页不再通过固定 `pageSize=200` 读取媒体后内存派生统计和列表。
3. 卡片顺序和隐藏状态由稳定 ID 配置驱动，并能跨进程重建保持。
4. Bottom Sheet 支持拖拽排序、隐藏/显示、恢复默认和无障碍替代操作。
5. 统计卡片、继续观看、最近添加、我的合集、常用文件夹、需要处理均按空状态条件渲染。
6. 顶部栏、底部导航和内容滚动边界正确，内容不会被固定底栏遮挡。
7. 默认浅色配色符合 `02-color-system-components.html`，无动态配色、深色入口或临时 Hex。
8. 缩略图调用遵循 `docs/11-compose-thumbnail-prefetch-plan.md` 的项目接口和缓存一致性要求。
9. 新增单元、Repository、Compose、导航和真机验证通过；既有权限、扫描、播放、视频界面、整理和设置回归通过。
10. 旧首页全量查询、旧统计字段、临时 Demo 数据和无效兼容代码已删除。
