## 1. 路线图目标

影里（YingLi Player）的目标是一款本地优先、免费、无广告、无遥测的视频播放器和媒体管理中心。它首先解决“快速找到并播放本地视频”，随后把分类、标签、集合、文件整理和视频处理整合到同一套媒体实体与任务模型中。

路线图必须同时满足四个条件：

1. 每个阶段都有可安装、可验证的产物，而不是只增加尚未可用的底层代码。
2. 播放器、媒体库、整理和处理之间通过稳定的领域模型连接，页面不直接操作文件或播放器实例。
3. 性能、权限和文件安全是阶段出口条件，不在功能完成后再补救。
4. 后续能力可以扩展，但不能因为未来的 GIF、转码、去重或保险库需求提前引入重量级依赖。

### 1.1 规划层级与阅读顺序

路线严格采用四层结构，避免把产品目标、页面功能和技术任务混在同一层：

```text
产品阶段（为什么交付）
  -> 版本里程碑 M0-M12（交付什么结果）
    -> 能力包：产品壳 / 媒体基础设施 / 播放 / 媒体库 / 整理 / 处理 / 安全（形成什么闭环）
      -> 页面、领域模型、系统能力、异常处理和验收任务（如何实现和证明完成）
```

产品阶段依次为：

1. **P0 首版核心闭环**：M0-M6，完成“授权扫描 -> 找到视频 -> 播放 -> 整理 -> 安全管理文件 -> GitHub 发布”。
2. **P1 本地视频处理**：M7-M10，先建立任务基础设施，再依次交付切片、压缩/转换和安全去重。
3. **P2 隐私安全域**：M11，应用锁和真实加密保险库独立评审、独立验收，不作为普通隐藏功能的延伸。
4. **P3 数据验证后的扩展**：M12，只有真实样本证明必要时，才立项 GIF、相似/片段去重、第二内核等能力。

每个里程碑内部都按“用户结果 -> 页面与交互 -> 领域模型 -> 数据/系统能力 -> 异常与恢复 -> 性能/无障碍/测试出口”展开。设计 Token、隐私、文件安全和可访问性是横贯所有阶段的门禁，不是 M6 才补的收尾事项。

## 2. 冻结基线

### 2.1 产品结构

```text
首页
  继续观看 / 最近添加 / 统计 / 常用入口

视频
  全部视频 / 文件夹与媒体源 / 搜索 / 筛选 / 排序 / 多选管理

整理
  标签 / 收藏 / 播放列表 / 普通集合 / 智能集合

全局入口
  右上角：处理中心、设置

上下文页面
  视频详情、播放页、搜索结果、筛选面板、任务详情、设置二级页
```

手机使用“首页 / 视频 / 整理”三项底栏，紧凑宽度之外根据窗口尺寸切换为导航轨或等价侧边导航。播放页隐藏一级导航，优先显示视频本身。

### 2.2 首版范围

首版完成标准为播放、媒体库和整理的基础闭环，具体包含：

- Android 12（API 31）及以上，首版只用当前连接真机 Xiaomi M2012K11AC（Android 13/API 33）验收；
- Kotlin 2.4.0、Jetpack Compose、Material 3、Media3、Room、DataStore、Coil；
- 全部文件访问作为默认授权路径，系统授权失败或用户拒绝后完整降级到 SAF/MediaStore；
- 首次授权后立即后台扫描，缓存首屏目标小于 500ms，1 万条媒体的增量轻量索引目标小于 3 秒；
- 首次引导允许立即添加或稍后添加；立即添加时推荐全部文件访问但不强制跳转，拒绝后使用 SAF/MediaStore；无缓存时以骨架和文字状态承接首次索引，不伪造百分比进度；
- 全部视频、文件夹、时长、扩展名、分辨率、画幅等媒体库组织维度；
- 搜索、组合筛选、升降序排序、网格/缩略图/列表视图；
- 瀑布流入口，但明确标记为实验功能，可关闭并回退到网格；
- 标签、收藏、播放列表、普通集合、智能集合、播放历史和已看状态；
- 播放续播、字幕、音轨、倍速、画面比例、队列、手势、后台行为、PiP 和系统媒体控件；
- 当前视频帧截图；
- 文件重命名、移动、回收站/删除确认、批量操作和结果摘要；
- 浅色、深色、跟随系统三种主题，以及已确定的黑白灰加功能色 Token；
- GitHub Releases 唯一分发，手动更新检查和资产摘要/签名校验。

首版不包含：GIF、视频切片、压缩/转换、视频去重、应用锁、加密保险库、网络媒体源、应用商店渠道、Android 12 以外版本的真机兼容承诺、第二播放内核和 FFmpeg 全量集成。

### 2.3 后续阶段

首版之后按以下顺序推进：

1. 处理中心基础设施和切片项目。
2. 压缩、封装转换和硬件编码回退。
3. 完全重复与相似视频检测，最后再评估片段级检测。
4. 应用锁和真实加密保险库。
5. 在真实用户样本证明需求后，才重新评估软件解码、FFmpeg 或第二播放内核。

### 2.4 原型基线与不可漂移约束

本路线已逐文件研读 `prototypes` 下全部 HTML 源码、CSS Token、语义属性和交互脚本。原型是视觉与信息架构基线，不等于对应功能已经进入当前版本。

| 原型 | 冻结结论 | 路线约束 |
| --- | --- | --- |
| [`01-navigation-style-prototypes.html`](../prototypes/01-navigation-style-prototypes.html) | 最终采用 F“自适应三栏”；手机为“首页 / 视频 / 整理”三项底栏，宽屏切换导航轨；处理中心和设置是全局辅助入口；首页、视频、整理具有明确内容骨架；存在当前播放胶囊/迷你播放器概念。 | M0 先交付自适应导航壳和页面状态容器；M2 接入当前播放状态；M3/M4 交付三个一级页；M5 再交付可操作迷你播放器。处理中心在 M7 有真实任务能力前默认隐藏，不发布空壳入口；设置始终不占一级导航。 |
| [`02-color-system-components.html`](../prototypes/02-color-system-components.html) | 无彩结构性选中，钢蓝用于焦点/信息/处理中；浅色 B、深色 A；播放器纯黑画布与白色 100/70/40 控件层；三层 Token、标签色板、状态容器、scrim、系统栏、edge-to-edge、空/加载/禁用/错误态及 Compose/XML 导出。 | M0 建立单一 Token 事实源、ColorScheme/XML 生成与基础组件状态矩阵；M2 建立播放器 scrim/buffer/played/seek-dragging/倍速 Token；以后每个页面里程碑都必须用同一组件体系验收，禁止逐页面临时配色。 |
| [`03-functional-color-brightness-comparison.html`](../prototypes/03-functional-color-brightness-comparison.html) | 功能色以 OKLab A-E 五档比较，最终为浅色 B、深色 A；钢蓝/红/琥珀/绿分别表达信息、危险、警告、成功；正文至少 4.5:1，UI 边界/图标至少 3:1。 | M0 建立安全配对矩阵和自动对比度检查；每个阶段新增 Token/组件必须通过浅色、深色和播放器上下文审计；深色模式不简单反转，表面层级遵循“海拔越高、表面越亮”。 |

原型还冻结以下跨阶段细节：颜色不是唯一状态线索；标签颜色用圆点/中性文字等形态与语义整色容器区分；系统栏和 edge-to-edge 分浅色、深色、播放器三套映射；播放画面上的观看进度使用无彩表达，不能误用成功绿。

> 校验边界：本轮已完成三个 HTML 的源码级研读；当前运行环境没有可用浏览器实例，未进行实际渲染、响应式断点和交互手感复核。实现阶段仍需在浏览器或 Android 真机上进行视觉验收。

## 3. 外部调研如何影响路线

| 来源 | 已验证结论 | 路线图影响 |
| --- | --- | --- |
| Android `MANAGE_EXTERNAL_STORAGE` | 全部文件访问必须声明权限，并通过 `ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION` 进入系统设置；可访问共享存储和 `MediaStore.Files`，但不能访问其他应用的专属目录。 | 授权引导是 M1 的显式系统流程；拒绝后保留 SAF，不把系统授权失败当作应用内部故障。 |
| Android MediaStore | Android 11+ 提供 `createWriteRequest`、`createTrashRequest`、`createDeleteRequest`；Android 12+ 可在满足条件时使用媒体管理特殊权限。 | 文件编辑和删除必须经过系统确认或已授予权限，默认先回收站，永久删除为二次确认。 |
| Media3 MediaSessionService | Player 和 MediaSession 应放在独立 Service；UI 通过 MediaController 连接；支持通知、外部控制和播放恢复。 | M2 先建立播放会话边界，播放页不拥有播放器实例；后台播放和系统通知作为 M5 验收项。 |
| Media3 Transformer | 支持转码、裁剪、效果和部分 transmux；任务异步执行，可查询进度并取消；单素材 MP4 的部分裁剪可优化，但不代表所有容器都是无损。 | M7 先建任务状态机；M8 以 MP4/稳定输出为边界，精确切片和无损快速切片必须在 UI 上区分。 |
| WorkManager 长任务文档 | 长任务可借助前台服务运行，但 Android 16 起可能消耗 JobScheduler 配额；用户主动任务可考虑直接前台服务或用户发起的数据传输任务。 | 首版不引入 WorkManager；处理阶段先做执行器 Spike，再决定直接前台服务与 WorkManager 的分工。 |
| Compose Window Size Classes | 窗口尺寸是动态的，不能用“是否平板”判断；尺寸变化、折叠和多窗口都可能改变布局。 | M0 建立自适应导航状态；M3 以 compact/medium/expanded 窗口测试导航、筛选面板和详情页。 |
| Baseline Profiles / Macrobenchmark | Baseline Profile 优化启动和关键交互，官方建议同时测 TTID、TTFD 和帧性能。 | M6 才加入项目级 Baseline Profile，先用真实媒体库任务定义关键用户旅程，不在功能未稳定时提前优化。 |
| Room 迁移文档 | 应导出 schema，使用 `room-testing` 测试单步和全量迁移。 | M0 建立 schema 版本策略；正式版高风险迁移前生成恢复点，M6 将迁移测试作为发布门槛。 |
| GitHub Releases API | Release 和 asset 有独立查询、摘要、大小、状态和下载地址字段。 | GitHub 更新器只访问 GitHub API/资产地址，不上传媒体或设备标识；更新失败不影响离线功能。 |
| Next Player / Only Player | Compose + Media3 + Room + DataStore 可覆盖本地媒体库、设置、会话和多窗口；媒体事实与播放状态应分离。 | 复用其边界思想，不复制其网络源、FFmpeg 扩展或具体版本；首版用手动依赖组装，不引入 Hilt。 |
| Aves / TagSpaces | 标签、条件组合、动态集合和批量编辑应相互独立；AND/OR/NOT 是高级筛选的常见模型。 | M3 先做筛选模型，M4 交付一层 `CompositeTag` 与智能集合；前者只表达标签条件，后者保存跨字段完整规则。 |
| LosslessCut | 片段、标签、项目和截图可以成为独立编辑数据；无损输出和转码应区分。 | M8 采用切片项目 + 片段列表 + 导出快照，不覆盖源文件。 |
| Files by Google / Google Photos / Czkawka | 重复组必须先复核再删除；完全重复和相似视频是不同检测成本；缓存能显著降低二次扫描成本。 | M10 分离完全重复与相似视频两个模式，分别提供证据和复核；片段重复后置，不与删除动作绑定。 |

## 5. 阶段详细计划

### M0 - 基础工程与产品壳

**目标**：建立可持续迭代的最小工程边界，先让构建、导航、主题和测试稳定。

**功能与工程任务**：

- 创建单 Activity Compose 工程，锁定 Kotlin 2.4.0、AGP 9.3.1、Gradle 9.5.0、JDK 21、compile/target 36、minSdk 31；
- 建立 Version Catalog，集中管理 Compose BOM、Media3、Room、DataStore、Coil、Coroutines 和 DocumentFile；
- 首版保持手动构造函数注入和工厂组装，不引入 Hilt/Koin；
- 建立 `AppState`、导航事件、窗口尺寸状态和三个一级页面占位；
- 按原型 F 建立自适应导航：compact 为“首页 / 视频 / 整理”三项底栏，medium/expanded 为导航轨；处理中心与设置走全局辅助入口，不占一级导航；
- 为三个一级页面分别建立可保存的滚动、排序、筛选、视图模式状态容器；播放页隐藏一级导航，退出时恢复来源页面状态；
- 建立浅色、深色、跟随系统三套主题映射；正式采用浅色 B、深色 A，动态颜色默认关闭；
- 建立三层 Token 单一事实源：Material `ColorScheme`、扩展功能色、组件 Token；由同一源生成 Compose 颜色对象与 XML Light/Dark，禁止手工维护两份数值；
- 建立深色表面海拔、状态层、scrim、阴影、文本选中、滚动条、系统栏和 edge-to-edge 的主题映射；
- 建立安全颜色配对矩阵和自动对比度检查，正文至少 4.5:1、UI 边界与图标至少 3:1；
- 统一 Tabler Icons 优先、Material Symbols 备用的图标适配接口；
- 建立 Room schema 版本 1、DataStore 偏好、统一错误模型和日志分级；
- 建立单元测试、Room 测试、Compose 关键导航测试和当前真机安装脚本；
- 建立 Debug/Release 的最小构建和 R8 规则，暂不创建网络层或第二播放内核。

**不在 M0**：媒体扫描、播放器初始化、完整设置页、处理任务、应用锁。

**退出条件**：

- `assembleDebug` 和 `assembleRelease` 成功；
- 首次启动只显示壳和可用导航，不初始化完整媒体库；
- compact 窗口使用底栏，中等/expanded 窗口使用导航轨或等价布局；
- 三个一级页面来回切换后，各自状态不串页、不丢失；处理中心在 M7 之前不显示无功能的空入口；
- 主题切换不改变页面状态；
- 最小触控目标为 48dp，关键文本和图标具备语义描述；
- Token 生成物与 HTML 原型选择一致，颜色配对自动检查通过；
- 基础 schema 和迁移测试可以运行。

### M1 - 媒体源、授权与增量索引

**目标**：在真实 Android 设备上完成“授权 -> 扫描 -> 媒体列表”的第一个可用闭环。

**授权流程**：

1. 首次引导允许用户选择“现在添加媒体”或“稍后在首页添加”，不在冷启动时自动跳转权限设置。
2. 用户选择添加媒体时，先解释全盘媒体管理、跨目录重定位和文件操作用途；“全部文件访问”是推荐默认路径，但只有用户点击授权动作后才进入 `ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION` 系统页，同页明确提供 SAF 目录选择替代项。
3. 返回后使用 `Environment.isExternalStorageManager()` 验证结果；失败只显示原因和 SAF 降级入口。
4. SAF 模式使用 `ACTION_OPEN_DOCUMENT_TREE`，持久化 URI 权限，支持添加多个目录。
5. 记录授权模式、卷标识、最后同步时间、可访问状态和用户排除规则。

**索引任务**：

- 建立 `MediaSource`、`MediaItem`、`MediaLocation` 三类领域实体；
- `MediaItem` 表示内容实体，`MediaLocation` 表示物理文件位置；标签、收藏和播放状态挂在内容实体，去重和文件删除针对位置实体；
- 使用 MediaStore 和直接共享存储访问建立轻量索引，文件 I/O 在 `Dispatchers.IO`；
- 首先保存 URI、名称、大小、修改时间、扩展名、容器和可播放初判，再后台解析时长、分辨率、画幅、编码和轨道；
- 以稳定媒体标识、卷/文档 ID 和文件属性做增量重定位，候选冲突时才异步计算内容指纹；
- 监听 MediaStore 变化并提供手动全量扫描；
- 扫描不锁定浏览和播放，新媒体增量加入列表；
- 默认排除缓存、`.nomedia`、系统目录和应用数据；
- 缩略图按当前可见项、继续观看、最近添加的优先级异步生成，普通缓存使用 LRU；
- 权限失效、移动、可移动存储离线和解析失败都保留可解释状态，不立即删除索引。

**性能出口**：

- 有缓存时首屏目标小于 500ms；
- 1 万条媒体增量轻量索引目标小于 3 秒；
- 正常秒级扫描不展示持续进度；超过阈值才出现轻量更新状态和诊断入口；
- 首次无缓存时显示结构化骨架与“正在建立媒体库”文字，不显示虚构百分比；选择稍后添加时进入带添加入口的空首页；
- 不在主线程执行文件扫描、媒体解析、哈希或缩略图生成。

### M2 - 播放垂直切片

**目标**：把 M1 的任意媒体安全地交给 Media3，并形成可重复验证的播放闭环。

**播放域实现**：

- 由 `MediaSessionService` 持有 ExoPlayer 和 MediaSession；
- 播放页通过 MediaController 订阅状态和发送命令；Composable 不创建播放器实例；
- 支持从媒体卡、详情、外部 Intent 和当前筛选结果打开；
- 首次从头播放，已有进度默认回退 3 秒，接近开头钳制为 0；
- 保存当前媒体、位置、播放速度、字幕/音轨和画面比例；
- 区分 URI 权限失效、文件损坏、解码器不支持和用户取消；
- 先实现播放/暂停、进度、音量、全屏/方向、返回和重试等主控；
- 播放页默认纯黑，视频画面优先，控件自动隐藏但保留可访问入口；浅色/深色/跟随系统只改变控制层、面板和系统栏，视频画布始终纯黑。
- 按配色原型建立播放器专用 Token：上下 scrim、白色 100/70/40 控件层级、buffer、played、seek dragging、倍速选中和禁用态均保持无彩；任意视频帧下时间文字仍满足 4.5:1；
- 建立“当前播放胶囊”的只读状态模型，供 M5 的迷你播放器复用；M2 不在一级页面提前暴露未完成交互。

**测试集**：

- H.264/AAC MP4 作为基线；
- HEVC、VP9、AV1、MKV/WebM、4K/HDR、内嵌/外挂字幕、多音轨和损坏文件作为逐项样本；
- 每个样本记录是否能打开、首帧耗时、音视频同步、丢帧、轨道切换、旋转恢复和权限错误。

**退出条件**：从媒体库打开、暂停、退出、重新进入和恢复播放均成功；旋转和 Compose 重组不重建或丢失会话；测试样本失败时有明确错误而非崩溃。

### M3 - 媒体库工作台

**目标**：让用户可以在不进入设置的情况下找到、筛选、排序和安全操作视频。

**页面与视图**：

- 视频页默认中等密度网格；支持全部视频、文件夹/媒体源和最近添加入口；顶部分组只承载媒体维度，标签通过筛选面板或整理页进入；
- 正式视图为网格、缩略图、列表；瀑布流以实验标签提供并允许关闭；
- 网格标题最多 1 行，列表最多 2 行，详情和编辑页显示完整名称；
- 视图、密度、排序和显示字段按页面状态保存；
- 视频页离开再返回时恢复滚动、分组、搜索、筛选、排序、视图和密度；不同主分组分别记忆视图与排序，临时筛选只保留当前会话，显式保存后才成为智能集合；
- 手机筛选使用可扩展到全高的模态 Bottom Sheet，宽屏使用适配的侧面/模态面板；
- 搜索入口在三个一级页面统一使用图标展开；默认匹配文件名和显示标题，结果按视频、文件夹、标签、播放列表和智能集合分组，技术字段可选且不提供搜索建议；
- 筛选区域分为“全部满足、任一满足、排除”，支持标签、文件夹、时长、后缀、分辨率、画幅和播放状态；
- 多标签默认进入“同时满足全部标签”，高级模式可切换“满足任一”和“排除”；组合标签是一层可复用规则，不允许嵌套，智能集合则可保存跨字段完整条件；
- 排序支持最近添加、时长、名称、播放次数等字段及升序/降序。

**批量与文件安全**：

- 长按进入多选，顶部显示数量和退出，底部显示高频动作；
- 批量标签、收藏、播放列表、移动、重命名、隐藏、回收站和取消选择都返回逐项结果；
- 通过 MediaStore 写入/删除请求或全部文件访问权限执行文件操作；
- 默认先进入统一的影里回收站页面；底层优先使用 MediaStore 系统回收站，能力不足时使用受控降级实现；永久删除为明确的二次确认；
- 批量操作不能因为单个 URI 失败而静默丢失其他结果。

**退出条件**：在 1 万条轻量索引上滚动和筛选保持可用；筛选条件可解释、可清除；文件操作不会误删源文件；实验瀑布流可回退到网格。

### M4 - 整理、集合与首页

**目标**：让媒体库从“文件列表”升级为可长期使用的个人媒体管理中心。

**组织模型**：

- `Tag`：自由用户标签，可设置受控颜色；
- `CompositeTag`：一层组合标签，引用原子标签和匹配规则，展示方式接近普通标签但不允许嵌套；
- `Favorite`：单媒体收藏状态，不伪装成标签；
- `Playlist`：人工顺序，支持拖动和显式加入/移除；
- `SmartCollection`：保存筛选规则，不复制媒体列表；
- 组合标签只表达标签条件，不能替代能保存任意字段、排序和播放状态的智能集合；
- 应用标签、播放状态和文件内元数据分离，默认不静默写回媒体文件。

**首页**：

- 固定默认顺序：继续观看 -> 最近添加 -> 媒体统计 -> 常用入口；
- 用户可以隐藏、恢复和排序首页模块；
- 继续观看横向卡显示进度和上次播放位置；
- 统计数字点击后携带条件进入视频页；
- 空模块不占用首屏；
- 返回首页恢复滚动和模块状态。
- 迷你播放器是否出现由设置控制；启用时只要存在未结束会话，离开播放页即显示；关闭该设置不影响 MediaSession 和系统通知。
- 一级导航壳遵循 01 原型：首页、视频、整理均使用同一层级语法；处理中心和设置仅为辅助入口，不因业务增多扩张为第四、第五个底栏项。

**退出条件**：用户可以从视频卡创建标签/收藏/播放列表，可以从标签或智能集合反向播放，应用重启后关系和页面状态不丢失；删除媒体不会自动删除标签关系，清理策略由索引维护决定。

### M5 - 高级播放与系统集成

**目标**：把播放器从“能播放”提升为可靠的长期播放会话。

**控制与手势**：

- 播放/暂停、进度、前后项、音量、倍速、画面比例、旋转和锁定；
- 左右/上下手势可配置，按钮提供等价命令；
- 进度缩略图、双击快进/后退和拖动 seek 作为默认克制方案；
- 选中、处理中、缓冲和错误使用图标 + 文字 + 形状，不依赖颜色唯一表达。
- 完成当前播放胶囊/迷你播放器：仅在有有效播放会话且播放页不在前台时出现；点击返回播放页，提供最小播放/暂停与关闭操作；无会话时完全隐藏。
- 迷你播放器作为设置项默认提供，用户关闭后不显示应用内胶囊，但不终止播放会话或系统通知；

**字幕与轨道**：

- 内嵌和外挂字幕，多字幕轨、多音轨；
- 按视频记忆轨道、字号、位置、样式和延迟，可切换全局默认；
- 外部字幕通过系统文件选择器加载并持久关联；
- 编码失败提供常见编码尝试和预览，不覆盖原字幕。

**系统行为**：

- 播放和 MediaSession 在前台服务中运行，通知和锁屏控件由会话状态驱动；
- 视频离开应用默认暂停，后台播放需用户主动开启；
- 遵守音频焦点，耳机/蓝牙断开默认暂停，恢复焦点不自动播放；
- PiP 手动进入为主，自动进入作为可选设置；
- 结束页提供重播、播放下一项和返回详情，连续播放默认关闭；
- 外部 Intent 视频不自动入库，但默认保存历史和进度；无痕模式下不产生任何记录；
- 队列区分当前列表、临时队列和持久播放列表，显示队列来源；
- 截图使用当前帧并保存为独立结果，不影响播放状态；
- 保险库能力尚未实现，因此首版不展示保险库入口；不为未交付功能预埋可见空壳页面。
- 播放器锁定时只保留解锁、播放/暂停和系统返回提示，隐藏其他按钮并禁用画面手势；

**退出条件**：冷启动、旋转、进入后台、从最近任务移除、通知控制、耳机断开和 PiP 场景均有测试结果；系统控制不能暴露不存在的媒体信息；播放服务在 `onDestroy` 完整释放资源。

### M6 - 首版硬化与 GitHub 发布

**目标**：把可用开发版本变成可以在 GitHub Releases 分发的首版。

**设置与视觉**：

- 完成设置二级页：主题、首页布局、媒体库视图/字段、播放器手势/轨道/后台播放、媒体源、回收站、备份和诊断；
- 浅色、深色、跟随系统分别验证，播放页纯黑上下文独立映射；
- 按 4dp/8dp 间距、48dp 触控目标、正文 4.5:1 和组件边界 3:1 验收；
- 所有状态有内容描述、文字或形状补充；
- 对三层 Token 的 Compose/XML 生成物做一致性测试；新增组件逐项覆盖 enabled、pressed、focused、selected、disabled、loading、success、warning、error；
- 自动执行浅色 B、深色 A 和播放器上下文的安全配对矩阵检查；标签颜色以“圆点 + 中性文字”等形态与语义整色容器隔离；
- 实机验证浅色、深色、播放器三套系统栏/edge-to-edge 映射，深色高海拔表面只能变亮，不能简单反转浅色值；
- 用户自定义按钮和动态颜色暂不作为首版默认能力。

**数据可靠性**：

- 导出 Room schema，覆盖所有正式迁移路径和高风险恢复点；
- 开发阶段允许清理重建，正式发布后的数据库格式必须版本化并提供迁移；
- 备份默认排除私密内容、密钥和完整路径，导出前显示摘要；
- 重置设置、播放数据、整理数据、索引和全部应用数据分别提供影响范围；
- 文件写入使用临时文件 + 原子替换，任务取消后半成品不入库。

**性能和稳定性**：

- 使用 TTID/TTFD、点击到首帧、扫描耗时、丢帧、内存峰值和安装包体积建立基线；
- 首屏只读缓存，扫描和缩略图不阻塞启动；
- 在关键路径稳定后加入 Baseline Profile/Macrobenchmark，覆盖启动、打开视频页、滚动媒体库、打开详情和首帧播放；
- 当前唯一发布验收设备为 Android 13 真机，其他 Android 12+ 版本标记为未验证；
- 运行 Room、MediaStore/SAF、MediaSession、播放器、文件操作、主题和关键导航测试。

**发布流程**：

1. 生成 Release APK，固定应用签名和版本号。
2. 生成 SHA-256 摘要，记录 ABI、版本、变更、权限变化和已知限制。
3. 在 GitHub Release 上传通用 APK，可附加 ABI 优化包；
4. 应用只访问 GitHub API/资产地址检查更新，不携带媒体、设备标识或行为数据；
5. 下载后校验摘要和 APK 签名一致性，失败资产立即清理；
6. 未允许安装未知来源属于系统问题，应用不主动引导修改设置；
7. 发布后观察崩溃、ANR、解析失败、扫描耗时和设备兼容反馈，反馈仅由用户主动提交。

**退出条件**：首版功能规格全部映射到测试用例；GitHub Release 可由干净 Android 13 设备下载、安装、授权、扫描、播放、整理和更新；离线状态不影响核心功能。

### M7 - 处理中心基础设施

**目标**：在首版稳定后引入通用处理任务模型，不先实现所有处理算法。

M7 才激活 01 原型中的处理中心全局入口和首页处理状态模块。入口显示进行中与未查看失败任务数量；没有任务时不制造长期角标，首页没有处理状态时不占版面。

**领域模型**：

- `ProcessingTask`：类型、输入快照、输出目录、参数快照、状态、进度、错误、时间和恢复信息；
- `TaskLog`：用户可读摘要和可导出的诊断日志；
- `OutputArtifact`：输出 URI、大小、校验、派生自关系、入库选项和结果状态；
- `ProcessingProject`：切片等可编辑草稿，与具体导出任务分离。
- 提交任务时保存“完成后加入媒体库”选项；已授权/已监控输出目录默认开启并记住偏好，结果页提供摘要与撤销入口；
- 主动取消立即清理半成品并保留可重试任务记录；执行失败可按配置短期保留诊断文件，并提供立即清理；

**执行器 Spike**：

- 首先用 Media3 Transformer 验证裁剪、封装、转码、进度、取消和错误回调；
- 评估用户主动长任务使用专用前台服务，清理/重试等非交互任务再考虑 WorkManager；
- 记录 Android 16 JobScheduler 配额影响，不默认把所有任务塞进长时间 WorkManager；
- 所有执行器通过统一接口接入，不让 UI 依赖 Transformer 类型；
- 任务运行时限制并发，低电量、高温和空间不足时降级或暂停。

**退出条件**：任务在应用重启后仍能显示真实状态；取消、失败、重试、结果摘要、临时文件清理和入库选择都可验证；源视频不被任务破坏。

### M8 - 切片项目与 GIF 技术预研

**目标**：先实现可控、可恢复的单源视频多片段工作流。

**切片范围**：

- 一个源视频对应一个切片项目；项目自动保存草稿；
- 片段有稳定 ID、起止时间、名称、标签、选中、导出状态和顺序；
- 支持时间轴、秒级输入、关键帧跳转和帧级微调；
- 默认精确切片，同时提供关键帧无损快速切片，并明确可能的时间偏移；
- 片段允许重叠，但导出前显示重复时长成本；
- 单个导出、勾选批量导出、统一结果摘要和“是否加入媒体库”选项；
- 输出保持“派生自”关系，不覆盖源视频。

**GIF 单独决策**：

- Media3 Transformer 当前目标是音视频输出，不把 GIF 当作现成能力；
- 先做帧抽取、调色板、尺寸、帧率和编码体积的技术 Spike；
- 若必须引入 GIF 编码器或 FFmpeg，先评估包体、ABI、许可证和设备内存，再单独立项；
- Spike 未通过前不在界面暴露 GIF 入口。

### M9 - 压缩与格式转换

**目标**：以固定预设为主，提供可解释的质量、体积和兼容性结果。

- 预设以质量/体积目标 + 最大分辨率表达，不直接暴露 CRF/GOP 等底层参数；
- 支持封装转换和重新编码，页面明确区分“快速封装”和“重新编码”；
- 提交前分析 HDR、字幕、多音轨、画幅、编码器和空间需求；
- 硬件编码优先，能力不满足时说明软件回退的时间、发热和体积；
- Media3 稳定输出先作为边界，新增容器通过独立处理后端，不污染播放内核；
- 无法保留附加轨道时默认阻止提交，用户明确选择烧录、单轨或放弃；
- 任务参数保存快照，结果保存摘要、校验、派生关系和入库选项；
- 输出默认位于源视频所在目录下的独立 `YingLi-Output` 子目录；权限不足时回退到用户已授权目录并解释原因，不静默覆盖源文件。

**退出条件**：至少完成 MP4 稳定输出、预设覆盖、硬件回退提示、空间检查、取消/失败恢复和结果入库；每个输出都能回到源视频和任务详情。

### M10 - 视频去重

**目标**：提供安全的重复组复核和回收站清理，不做无确认的自动删除。

**阶段顺序**：

1. L0：大小、时长、分辨率、画幅、编码等事实预筛选。
2. L1：完全重复，按大小分组后计算部分哈希和完整哈希。
3. L2：重编码、缩放或轻微编辑后的相似视频，抽取多时间点帧并使用感知哈希；与完全重复一起属于 M10 的正式范围，但入口、阈值和结果证据必须分开。
4. L3：部分片段/长短视频关系，涉及滑动窗口或音频指纹，后置到 M12，不属于 M10 完成条件。

**用户流程**：

```text
选择来源 -> 选择检测类型 -> 扫描 -> 重复组列表 -> 组内播放/对比 -> 修改建议保留 -> 移入回收站
```

- `DuplicateScan` 保存范围、模式、阈值、算法版本和状态；
- `DuplicateGroup` 保存组成员、数量、总大小和预计释放空间；
- `DuplicateCandidate` 保存证据、建议保留、保护来源和用户选择；
- `HashCache` 以媒体身份、大小、修改时间和算法版本为缓存键；
- 完全重复与相似视频使用两个显式模式；相似模式首版提供严格/均衡/宽松预设，不暴露任意阈值，结果解释抽帧相似证据但不把算法术语强加给普通用户；
- 保护目录只参与比较，不被自动勾选删除；
- “建议保留”必须给出依据并允许用户修改；
- 删除通过媒体服务/回收站执行，成功后刷新媒体索引。

**退出条件**：完全重复和相似视频两种模式都能形成可播放、可并排/同步对比的重复组；用户能覆盖所有自动建议；删除前显示范围、数量和预计空间；取消扫描不会破坏已有索引；第二次扫描使用缓存且明显快于第一次。

### M11 - 应用锁与真实加密保险库

**目标**：在首版和处理能力稳定后，单独交付隐私安全域。

**实施顺序**：

1. 威胁模型、数据分类、泄露面和不可恢复承诺评审；
2. 应用锁：设备生物识别、设备凭据、应用密码/图案、限速、超时和密保恢复；
3. Keystore 密钥层：密钥不可导出，按设备认证约束使用；StrongBox 只在能力与性能评估通过后作为偏好；
4. 保险库容器：默认应用私有目录，允许迁移密文到授权目录；
5. 加密导入 -> 校验 -> 提交 -> 删除明文源的事务流程；
6. 独立受保护缩略图缓存、禁止截图、最近任务中性遮罩、通知/PiP/投屏隐私过滤；
7. 导出、备份和移出保险库提供显式二次确认和不可恢复警告；
8. 生物识别变化、密钥丢失、密文损坏和卸载场景进行恢复/不可恢复测试。

**退出条件**：普通媒体库无法看到保险库内容；系统通知和最近任务不泄露私密标题或封面；密钥不可通过普通备份导出；所有失败场景都有明确且不虚假的恢复说明。

### M12 - 需求验证后的扩展

以下能力不自动排入主线，必须在对应阶段完成后由实际数据证明价值：

- 片段级去重以及相似模式的任意高级阈值；
- GIF 编码；
- 软件解码、FFmpeg 或第二播放内核；
- 自定义播放器按钮的完全自由编排；
- 动态颜色或更多品牌主题；
- 网络媒体源、在线字幕和账户同步；
- Android TV、键鼠/遥控器专门焦点体系；
- 更广泛的多厂商真机兼容矩阵。

## 6. 跨阶段工作流

### 6.1 数据与迁移

- 每个 Room schema 变更先导出 JSON schema，再写迁移和 `MigrationTestHelper` 测试；
- 媒体事实、用户组织、播放状态、任务状态和安全状态分表/分域；
- 迁移前恢复点只保护应用数据库和设置，不复制源视频；
- 任何 URI、路径、授权模式变化都用媒体实体和位置实体表达，不把路径当作稳定 ID；
- 删除、移动、输出和保险库迁移都采用临时文件、校验、原子替换或提交后清理。

### 6.2 性能

每阶段都记录以下指标，M6 冻结首版基线：

| 指标 | 采集时机 | 首版要求 |
| --- | --- | --- |
| TTID/TTFD | 冷启动、暖启动、缓存有/无 | 首屏可见与可交互分开记录，不用单一启动时间掩盖扫描耗时 |
| 缓存首屏 | 有媒体库缓存启动 | 小于 500ms 目标 |
| 增量扫描 | 1,000 / 10,000 条媒体 | 10,000 条轻量索引小于 3 秒目标 |
| 点击到首帧 | MP4、HEVC、4K/HDR | 按设备建立基线，异常样本单独记录 |
| 列表帧性能 | 滚动、筛选、缩略图加载 | 不在主线程做 I/O，不出现可见阻塞 |
| 内存峰值 | 长列表、切换播放、截图 | 记录并设置回归阈值 |
| 安装包体积 | 每个 Release | 监控 ABI 和新 Native 依赖变化 |

M6 之后用 Macrobenchmark 覆盖启动、进入视频页、滚动、打开详情和播放首帧；Baseline Profile 只在关键路径稳定后生成。

### 6.3 测试策略

- JVM：ViewModel、筛选解析、排序、队列、任务状态机、去重分组和错误映射；
- Room：DAO、schema、单步迁移和从最旧版本到当前版本的全量迁移；
- 仪器：全部文件访问引导、SAF 降级、MediaStore 写入/回收站、播放器服务、MediaSession、截图和主题；
- 当前真机：完整媒体测试集、旋转、后台、PiP、耳机断开、存储卷离线、安装更新和真实文件操作；
- 静态/可访问性：语义描述、对比度、触控目标、字体放大和状态多线索表达；
- 处理阶段：每一种任务状态都测试取消、进程终止、空间不足、权限失效和输出冲突；
- 安全阶段：最近任务、通知、截图、分享、备份、密钥失效和卸载警告。

### 6.4 文档与可观测性

- 每个阶段完成后更新功能规格、数据模型、迁移说明、测试矩阵和已知限制；
- 诊断包只包含版本、设备/解码能力、脱敏日志和可选任务日志，不包含媒体、保险库内容、私密标题和完整路径；
- 失败消息优先告诉用户可执行的下一步；日志保留技术细节但不暴露敏感内容；
- 每次 GitHub Release 记录变更、权限、数据库版本、测试设备、已知格式限制和校验摘要。

## 7. 架构演进计划

### 7.1 M0-M6：单应用、按域分包

首版不强行拆成多个 Gradle module，先在单应用内保持稳定边界：

```text
app/
  core/model
  core/database
  core/datastore
  core/media
  core/designsystem
  core/common
  domain/
  feature/home
  feature/library
  feature/organize
  feature/player
  feature/settings
```

依赖方向固定为：

```text
Compose UI -> ViewModel -> UseCase（仅复杂业务） -> Repository -> 数据源
播放 UI -> MediaController -> MediaSessionService -> ExoPlayer
```

只有当编译时间、依赖作用域或测试隔离出现真实问题时，才把稳定边界提取为 Gradle module。

### 7.2 M7-M11：按任务和安全域扩展

```text
feature/processing
  processing-domain
  processing-data
  processing-executor
  feature/task-center

feature/security
  app-lock
  vault
  secure-cache
```

处理执行器、去重算法和保险库加密均不能被 UI 直接调用。它们必须通过领域接口返回可持久化的状态、进度、错误和结果。

### 7.3 依赖引入门槛

| 依赖 | 默认阶段 | 引入条件 |
| --- | --- | --- |
| WorkManager | M7 评估 | 有可靠的非交互后台任务需求，并验证 Android 16 配额影响 |
| FFmpeg/其他 Native 后端 | M8/M9/M12 评估 | Media3 样本失败证明必要，且完成包体、ABI、许可证和性能评审 |
| Hilt/Koin | M6 后评估 | 依赖作用域真实复杂到手工组装造成重复或错误 |
| 网络客户端 | 不在主线 | 用户重新确认网络媒体源或 GitHub 更新之外的网络能力 |
| 分析/广告 SDK | 不引入 | 与无遥测、离线优先原则冲突 |

## 8. 发布与版本路线

### 8.1 内部渠道

- `0.x-dev`：仅当前开发设备验证，允许数据库重建和破坏性 schema 变更；
- `0.x-alpha`：完成 M1-M4 的真实媒体闭环，记录已知格式和权限限制；
- `0.x-beta`：M5 完成，稳定播放会话、主题、无障碍和文件操作；
- `1.0.0`：M6 完成，GitHub Release 对外分发；
- `1.x`：按 M7-M11 逐个独立交付，不把后续阶段标记成首版已支持。

### 8.2 GitHub Release 清单

每次正式 Release 必须包含：

- 版本号、发布日期、目标 Android 版本和数据库版本；
- 通用 APK，必要时附 ABI 优化包；
- SHA-256 摘要和 APK 签名校验说明；
- 新增功能、权限变化、迁移说明、已知格式限制和已验证设备；
- 可回滚的安装说明；
- 不静默下载、不通过第三方镜像分发、不采集媒体和行为数据。

### 8.3 版本升级与迁移

- 开发版升级可清理本地数据库重新扫描；
- 正式版从第一个公开版本开始维护迁移路径；
- 高风险迁移前写入短期数据库恢复点，成功后清理；
- 迁移失败保留原数据库和恢复点，向用户显示恢复/导出诊断选项；
- 任何格式或数据结构不兼容必须在 Release Notes 中明确说明。

## 9. 风险登记

| 风险 | 影响 | 预防与触发器 | 处理阶段 |
| --- | --- | --- | --- |
| 全部文件访问授权被拒 | 无法全盘扫描和跨目录重定位 | M1 明确系统授权用途；立即降级 SAF | M1 |
| 单真机无法代表 Android 12+ | 发布后设备差异 | 所有兼容结论标记设备范围；后续新增设备 | M6/M12 |
| Media3 格式覆盖不足 | 视频无法播放 | 真机样本分类；失败样本达到业务阈值后再评估后端 | M2/M12 |
| 扫描拖慢启动 | 首屏不可用 | 缓存优先、增量索引、后台缩略图、性能预算 | M1/M6 |
| 任务进程被系统终止 | 输出损坏或状态丢失 | 任务状态持久化、临时输出、恢复能力分级 | M7-M9 |
| Transformer 输出回退 | 质量/分辨率/编码与预期不同 | 提交前摘要、监听 fallback、结果记录 | M9 |
| 误删文件 | 用户数据损失 | 建议保留可修改、受保护路径、默认回收站、二次确认 | M3/M10 |
| 相似视频误报 | 删除错误媒体 | 与完全重复分入口；提供严格/均衡/宽松预设、证据和同步对比，必须人工复核 | M10 |
| GIF/FFmpeg 依赖膨胀 | 包体、许可证和性能风险 | 先 Spike，失败才引入独立后端 | M8/M12 |
| 数据库迁移失败 | 媒体关系和播放记录损坏 | schema 版本、恢复点、全量迁移测试 | M0/M6 |
| 保险库泄露 | 私密内容暴露 | 独立威胁模型、Keystore、缓存/通知/最近任务过滤 | M11 |
| 页面需求扩张 | 交付不可控 | 以首版范围和新增编号管理变更 | 全阶段 |

## 11. 每阶段通用完成定义

一个阶段只有同时满足以下条件才算完成：

- 功能有可用入口、空状态、错误状态、权限失败状态和返回路径；
- 数据模型、持久化、迁移和恢复行为已记录；
- 主线程没有文件 I/O、解析、哈希、加密或转码；
- 关键交互有 JVM/Room/仪器测试，当前真机完成对应场景验证；
- 浅色、深色、跟随系统和字体放大不发生重叠、截断或对比度违规；
- 每个新增组件都复用三层 Token，覆盖其适用状态；安全颜色配对矩阵自动检查通过；
- 页面遵循原型信息架构，一级导航状态、来源返回和窗口尺寸切换均有测试；
- 任务、文件操作和播放失败不会静默丢数据；
- 文档、Release Notes、已知限制和下一阶段依赖已更新；
- 阶段没有偷偷引入未批准的网络能力、Native 后端、广告或遥测。

## 12. 当前执行顺序

第一轮实现应严格按以下顺序开始：

1. M0：构建基线、导航壳、主题 Token、Room/DataStore schema 和测试骨架；
2. M1：全部文件访问引导、SAF 降级、媒体源和增量索引；
3. M2：MediaSessionService + MediaController + 基础播放；
4. M3：视频页、搜索、筛选、排序、视图和安全文件操作；
5. M4：整理页、标签、集合、历史和首页；
6. M5：高级播放、系统控制和当前视频帧截图；
7. M6：性能、无障碍、迁移、诊断、GitHub Release 和首版验收；
8. 首版发布后再启动 M7，不在 M0-M6 过程中预埋完整处理中心、去重或保险库。

每一轮开始前先从 `07-question-to-roadmap-traceability.md` 过滤该里程碑对应题号，形成实现清单；完成后逐条回填测试证据。出现新需求时新增编号和映射，不以直接修改旧结论的方式破坏追踪链。
