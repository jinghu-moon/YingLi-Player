### 1.1 ⚠️ P0 阻断项：D8 与"单一裁剪循环"的冲突 —— Q7 已定采用 D8-A（可行性待验证）

单个 `ClippingMediaSource(A, B)` 只提供 `[A, B]` 区间，**无法播放 A 之前的内容**；这与 D8 的"A 之前继续正常播放"以及"循环期间允许拖到区间外"**在能力上冲突**，且该冲突**与位置语义是绝对值还是片段相对值无关**（无论 U1 观察到哪种，冲突都存在）。

| 方案 | 含义 | 代价 |
|---|---|---|
| **D8-A：保留 D8**（**Q7 已定，采用本方案**） | 方案 B 需要额外的**切源/分阶段**设计（例如：进入区间前用未裁剪源，抵达 A 时切到裁剪循环源；离开区间时切回）或改用方案 A（手动 seek + 强制 `EXACT`） | 切源即重建 → 黑帧/位置抖动/通知刷新；复杂度显著上升；也可能最终退化为方案 A |
| **D8-B：保留单一裁剪循环**（**仅作为产品取舍备选项**） | 修改 D8：**激活后只能在 `[A, B]` 内播放与 seek**；并定义"激活瞬间当前位置不在区间内"的处理（钳到 A / 钳到 B / 拒绝激活并要求先定位） | 产品语义收窄：不支持"从 A 之前自然进入"；拖出区间会被钳回 |

**Q7 已定：采用 D8-A** —— 保留"A 之前正常播放、抵达 A 后开始循环"的既定体验；**不为了让单一裁剪源更简单而未经确认改成 D8-B**。

**本轮审核新增的关键约束**：

1. **切源方案失败时，回退到方案 A 也必须先验证是否满足"无缝"验收**（阈值见 §3.4）；方案 A（手动 seek + 强制 `EXACT`）**不能自动视为通过** —— 它同样可能在循环点出现**画面停顿 / 黑帧 / 音频间断**，必须与切源方案用同一口径实测对照（T0.2）。
2. **若切源方案与方案 A 都达不到无缝验收 → 作为产品取舍上报给用户决策**，可选项至少包括：
   - 接受轻微停顿（明确写入体验与验收口径）；
   - 收窄为 **D8-B**（改 D8，更新 §3.1 语义与 `docs/16`/`docs/17`）；
   - 换其它实现（例如可变裁剪等，取决于 U11 结论）。
   **不得默认"回退方案 A 即通过"。**

**阶段 0 必须给出结论**（含真机证据）：D8-A 的切源方案是否可行、方案 A 的对照结论、以及两者都不达标时的取舍上报。在该结论明确前：**不进入阶段 1/2 主线**。

### 2.2 ⚠️ 修正：AB 状态**不是单一权威源**（审核 P1；v3 补第三份）

原文档称"服务层已接 reducer、seek 会经过 limiter"，**高估了活跃链路的接线**。实际是：

- **播放页实际使用 `PlayerViewModel` 自己持有的一份 AB 状态**，并在本地调用 `AbLoopLimiter`（`feature/player/PlayerViewModel.kt:528` 一带）；
- 同时 `PlaybackSessionRuntime` 里**另有一份** AB 状态与 reducer（`app/playback/PlaybackSessionRuntime.kt:249` 一带）；
- **v3 补充（本轮核对）**：`PlaybackSessionClientBridge` 内**还有第三份** AB 状态（`app/playback/PlaybackSessionClientBridge.kt:42`），且它在每次 `publish` 时把自己的那份写回快照（`PlaybackSessionClientBridge.kt:226-241`，`abLoop = abLoop`）→ 会**覆盖**会话侧的取值。

→ 运行中的 UI 路径、会话路径、客户端桥接路径**并非同一个权威状态源**。**Q8 已定口径**：AB **状态与计数由会话 runtime 统一持有并做命令编排**，但 runtime **不直接拥有 Media3 的源重建实现** —— **建源、重建与位置续接由 engine/service 负责**；所有客户端实现**只能有一个权威 AB 状态源**，必须**删除其余实现**（含 `PlaybackSessionClientBridge` 的那一份，见 T1.1）。方案 B 的落地以前述收敛为前提（`AGENTS.md`：不留重复实现）。

### 2.3 ⚠️ 修正：媒体源重建边界与引擎接口不匹配（审核 P1）

- `PlaybackEngine.prepare` 接收的是**不透明 source handle + 起始位置**（`domain/playback/PlaybackSessionContracts.kt:418` 一带）；
- `ServicePlaybackEngine` **自己解析 URI** 并调用 `player.setMediaItem(...)`（`app/playback/ServicePlaybackEngine.kt:134` 一带），服务另设了带 `VaultAwareDataSource` 的 media source factory。

→ §4.1 的"包装当前媒体源""只在设 B/清除时重建"**不是可直接执行的接线方案**。必须先规定：

- 建源边界**如何接收** AB 区间；
- 如何**保留受保护源（保险库）的数据源配置**；
- **激活后再次调整 A/B** 时如何更新裁剪边界（原"只重建两次"与"胶囊允许继续设点"矛盾；**Q9 已定策略**，见 §4.1 第 3 点）。

### 2.4 ⚠️ 补充：位置映射的波及面（审核 P1）

引擎直接把 `player.currentPosition` / `player.duration` 发布为 timeline（`ServicePlaybackEngine.kt:308` 一带），截图请求取会话位置（`PlaybackSessionRuntime.kt:408` 一带），服务还用播放器位置保存播放进度与历史（`YingLiPlaybackService.kt:185` 一带）。

## 3. 目标行为规格（v2；v3 按 Q7–Q10 更新 §3.1/§3.2，并新增 §3.4）

### 3.1 循环语义

- **设 A**：以当前位置为 A；若该位置 **> B** → A/B 互换；若 **== B** → **拒绝/无操作**（不互换、不改状态，避免产生 `A == B` 违反不变量）；
- **设 B**：位置必须 **> A**，否则拒绝并给 `INVALID_AB_RANGE`；
- **帧吸附**（D5，审核修正）：**按帧索引计算**，避免非整数帧率的取整误差：
  `frameIndex = round(ms * fps / 1000)` → `snappedMs = round(frameIndex * 1000 / fps)`；
  - 无可用帧率（实测与容器都为 0/缺失）→ 原样返回毫秒；
  - 吸附后**若导致 A == B**（或 < 一帧间隔）→ 按相等边界规则拒绝/无操作；
  - 注释与文档声明：这是**名义帧率吸附**，VFR 素材不承诺命中真实帧边界（D13）；
- **激活**：A、B 都设置后立即生效；
- **区间外行为**：按 **Q7 = D8-A**（§1.1）——**A 之前正常播放、抵达 A 后开始循环、循环期间可拖到区间外**；该语义能否落地取决于**切源方案（U10）**；若切源与方案 A 都不达标 → 按 §1.1 上报产品取舍（含"收窄为 D8-B"这一选项；一旦收窄，本条需改写为"激活后仅 `[A,B]` 可播放/seek + 激活瞬间区间外位置的处理"）；
- **清除**：取消循环、清零计数；关闭胶囊**不**清除（D3）；
- **切歌/换媒体**：自动清除（`MediaChanged` 语义保持）；
- **循环计数**（D9）：必须来自**可区分的循环事件**，不得用"位置跨越 A"猜测（审核 P1，见 U2）；
- **AB 启用策略**（Q10 已定，v3 修正判定时机）：
  - **未知时长 或 不可 seek → 禁用**（循环区间不可定义）；
  - **非本地 / 受保护（保险库）媒体 → 按实际能力决定**（底层真能 seek 就可用，不因"来源类型"一律禁用）；
  - **判定时机是播放器准备完成之后**，按**真实 timeline 的 `duration` 与 seekability** 判定，**不是**按来源类型或最初 metadata 一律禁用 —— Vault 打开时传入的 source handle 时长可能是未知值（`app/playback/PlaybackSessionRuntime.kt:272` 一带把 `source.durationMillis` 写进 `mediaInfo`、而 timeline 是空的），准备完成后真实时长由引擎 timeline 提供（`app/playback/ServicePlaybackEngine.kt:308-312`：`durationMillis = player.duration...`、`isSeekable = player.isCurrentMediaItemSeekable`）；
  - 并给出用户可见的反馈口径（禁用原因可读）。

### 3.2 UI 与交互

- **入口**：托盘（主）、设置面板「工具」、顶栏溢出菜单（三处同一状态源，D10）；
- **托盘按钮**：图标 `a-b-2`；循环生效时**实心**；
- **AB 胶囊**：位置/几何/材质与截图胶囊**完全同源**（§3.3），内容 = A / B / 清除 / 关闭；**不自动暂停**（D6）；
- **带文字胶囊按钮**（审核 P2）：`A 00:12`、`B 设置`；
  - `48dp` 是**最小触控高度**，不是固定宽度 → 文字按钮必须**弹性宽度**；
  - 验收：**窄屏 / 横屏 / 系统字号放大**下不溢出、不截断语义（必要时缩字号但保持可读）；
- **进度条**：A–B **区间高亮** + 两端标记 + **计数文案 `循环 ×12`**（Q1 定稿）；
- **互斥**（D2，审核 P2 细分）：与截图的三个状态分别定义（v3 另补一条**异步晚到时序**）：
  | 截图状态 | 打开 AB 工具时 | 关闭 AB 时 |
  |---|---|---|
  | `Armed` / `Capturing` | 先结束截图会话（等价"关闭截图工具"）再打开 AB | 不恢复截图工具 |
  | `Preview`（预览卡/大图存在） | **保留预览卡与倒计时**（不销毁用户的截图结果），仅退出截图"工具模式" | 不影响预览卡 |

- **互斥 · 异步晚到（v3 补充，本轮审核最后一点）**：截图处于 `Capturing` 时打开 AB，除了要**结束截图会话**，还必须覆盖**截图的异步完成事件晚到**：

### 3.4 无缝性与精度的量化验收（v3 新增）

> 本节是"无缝"与"落点精度"的**唯一判定口径**，供 §1.1（D8-A 切源 vs 方案 A 对照）、T0.1/T0.2（阶段 0 对照）、T2.9/T2.10（阶段 2 落地验证）共同引用。**主观感受不能单独作为通过依据。**

| 项 | 通过条件（阈值） | 判定方式 | 依据 |
|---|---|---|---|
| 循环落点误差 | 每次回到 A 的偏差 **≤ 1 帧**；名义帧率 `fps` 下即 **≤ `1000/fps` 毫秒**（30fps → ≤33ms，60fps → ≤17ms） | 位置日志：每次回到 A 后立刻采样 `positionMillis`，与设定的 A 逐次求差 | 帧吸附（D5/D13）的最小可分辨单位就是 1 帧；≤1 帧等价于"落点与设定点落在同一帧内" |
| 无累积漂移 | 连续 **50 次**循环内，**第 50 次偏差不得显著大于第 1 次**（同一量级，不允许随次数单调增大） | 同上的 50 次采样序列，首末对比 + 观察是否单调漂移 | 累积漂移是"循环点用相对量重算"这类实现错误的直接症状 |
| 不得发生重新缓冲 | 循环点附近**不出现** `STATE_BUFFERING` / `onIsLoadingChanged(true)`；**日志统计次数 = 0** 才算通过 | 循环点前后各 1 秒的日志计数 | 一次重缓冲必然带来画面停顿/黑帧，是"无缝"的客观反例，且可用日志零成本判定 |
| 音视频间断 | 逐帧录像中循环点**无丢帧**（不出现帧时间戳空洞）；音频**无静音段超过 1 帧** | 逐帧录像 + 帧时间戳序列核对；音频静音段按采样判定 | 与"≤1 帧"同一尺度：一帧以内的衔接视为不可感知 |
| 主观 | **无可感知卡顿** —— 必须与上面四项客观数据**同时满足**，不能只凭主观 | 真机回放 | 主观只能作为"客观达标后"的补充确认 |

**基线说明**：以上阈值是**当前测试设备（`f3ba305a`，Android 16）**上的基线；**换 ROM / 芯片 / 解码器 / 素材（含 VFR）后必须重测并重新记录基线**，不得直接套用。若实测达不到阈值 → 按 §1.1 上报产品取舍，**不得降低本节阈值来"通过"验收**。

## 4. 架构设计（方案 B）与不确定点

### 4.1 媒体源包装（待细化，见 §2.3）

- 目标形态：AB 激活时 `LoopingMediaSource(ClippingMediaSource(builtSource, startUs = A, endUs = B), 无限)`；
- **必须先解决的接口问题**：
  1. 建源边界**如何接收 AB 区间**（`prepare` 目前只收不透明 handle + 起始位置）；
  2. 如何**保留受保护源的数据源配置**（`VaultAwareDataSource` 等 factory 配置不得因包装而丢失）；
  3. **激活后调整 A/B** 如何更新裁剪边界（"只重建两次"与"胶囊可继续设点"矛盾）→ 需明确策略（见 Q9）：优先**可变裁剪**（若 API 支持，在 **U11** 验证）；不可用时按"**设点成功提交后立即更新**"；或延迟到胶囊关闭时一次更新（该分支有强制要求，见 Q9 与 T2.3）；
- 重建后**位置续接**：重建前记录绝对位置，重建后 seek 回（区间外按 Q7 = D8-A 处理；若最终收窄为 D8-B，按 §1.1 的钳制规则处理）。

### 4.2 与既有机制的关系

| 机制 | 处理 |
|---|---|
| AB 状态所有权 | **按 Q8 收敛**：AB 状态与计数由**会话 runtime 统一持有并做命令编排**；**建源 / 重建 / 位置续接由 engine/service 执行**（runtime 不直接拥有 Media3 的源重建实现）；所有客户端实现**只有一个权威 AB 状态源** —— 必须核对并清理 `PlaybackSessionClientBridge` 内的那一份（`app/playback/PlaybackSessionClientBridge.kt:42`），不得残留第三份（T1.1） |
