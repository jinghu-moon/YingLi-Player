## 1. 文档目的

本文把前期问答、产品讨论、原型和调研结论归并为可用于产品设计、架构设计和开发拆分的功能规格。本文描述“系统应做什么”，不提前绑定具体页面组件或底层实现细节。

需求状态：

- **已确定**：已有明确回答，可进入设计和任务拆分；
- **待确认**：仅用于后续新增且尚未回答的变更；当前没有待确认项；
- **后续阶段**：方向已确定，但不要求首个可用版本交付；
- **不在范围**：当前明确不实现。

关键词：

- **必须**：验收所需的强制要求；
- **应该**：默认采用，只有明确理由才能偏离；
- **可以**：可选增强能力。

## 2. 产品定义

### 2.1 定位

影里（YingLi Player）是 Kotlin + Android 开发的本地视频播放器与媒体管理中心。产品以视频播放为基础，以媒体发现、分类、标签、集合、搜索、批量文件管理和后续视频处理为扩展。

### 2.2 核心原则

- 本地优先、离线可用，不把网络账户作为核心流程；
- 免费、无广告，不采集行为遥测；
- 播放器和媒体管理共用同一媒体实体、播放记录和权限模型；
- 首版把全部文件访问作为默认授权路径，但必须由用户在系统界面显式授权；拒绝后降级到 SAF/MediaStore；
- 普通用户使用预设完成任务，高级参数按需展开；
- 不用颜色作为状态的唯一线索；
- 不因未来功能提前增加当前不需要的页面和依赖。
- 只通过 GitHub Releases 分发，不适配应用商店发布流程。
- 不考虑 SMB、WebDAV 等网络媒体源，媒体库范围限定为本地及可移动存储。

### 2.3 平台基线

- Android 12（API 31）及以上；
- Kotlin 2.4.0；
- Jetpack Compose + Material 3；
- Media3 ExoPlayer + MediaSession；
- Room 保存媒体索引和业务数据；
- `MANAGE_EXTERNAL_STORAGE` 负责首版默认的全盘媒体管理；MediaStore + Storage Access Framework 负责发现、降级和用户授权目录访问。

完整技术版本见 [00-android-technology-selection.md](00-android-technology-selection.md)。

### 2.4 分发与版本

- GitHub Releases 是唯一正式发布源；
- 不为 Google Play、F-Droid 或国内商店建立独立包和更新流程；
- 应用更新不得影响离线播放、媒体库和整理功能；
- 提供手动更新检查和可关闭的低频自动检查，不静默下载；
- 默认稳定渠道，用户可选择接收 GitHub prerelease；
- Release 提供通用 APK，并可附加 ABI 优化包；
- 下载后校验资产摘要和 APK 签名；
- 影里不主动引导解决系统“安装未知应用”权限，由用户自行处理；
- GitHub 不可访问不影响任何离线功能。
- 正式版执行高风险数据库迁移前创建轻量本地恢复点，成功后按期限清理；开发阶段不承诺旧数据库兼容。

### 2.5 首版范围

- 首版完成标准是播放、媒体库和整理的基础闭环；
- 首版同时包含当前视频帧截图、实验性瀑布流和默认全部文件访问；
- GIF、视频切片/压缩/转换/去重、应用锁与保险库均按后续独立阶段交付；
- 后续阶段的方向和需求可以保留在本文，但不得进入首版验收清单。

## 3. 信息架构

### 3.1 一级页面

| 页面 | 职责 | 状态 |
|---|---|---|
| 首页 | 继续观看、最近添加、媒体统计、常用入口和用户加入首页的集合 | 已确定 |
| 视频 | 全部视频、文件夹/媒体源浏览、搜索、筛选、排序、视图和批量选择 | 已确定 |
| 整理 | 标签、收藏、播放列表、普通集合和智能集合 | 已确定 |

手机使用“首页 / 视频 / 整理”三项底部导航；中等及以上窗口宽度切换为侧边导航轨。播放页隐藏一级导航。

### 3.2 全局入口

- 处理中心位于顶部应用栏，显示运行任务数量、状态或失败提示；
- 设置位于顶部应用栏，不占一级导航；
- 三个一级页面都使用搜索图标进入搜索，不常驻搜索框；
- 每个一级页面按其内部分组保存独立子状态：滚动、视图和排序持久化，临时筛选只保留当前会话；显式保存的筛选进入智能集合。

### 3.3 上下文页面

- 视频详情；
- 搜索结果；
- 筛选面板；
- 标签/集合详情与编辑；
- 播放页；
- 视频处理创建页；
- 处理中心及任务详情；
- 应用锁与保险库（后续阶段）；
- 设置二级页面。

## 4. 首页

### FR-HOME-001 模块顺序

**状态：已确定。** 首页默认依次显示：继续观看、最近添加、媒体统计、常用入口。用户后续可以隐藏、恢复和排序模块。

### FR-HOME-002 继续观看

- 必须使用横向媒体卡；
- 必须显示观看进度和上次播放位置；
- 点击后直接恢复播放；
- 没有可继续内容时不占用首屏空模块。

### FR-HOME-003 最近添加

- 默认最多展示一行、6 条以内；
- 有更多内容时显示“查看全部”；
- 查看全部进入带有“最近添加”条件的视频页，返回时恢复首页位置。

### FR-HOME-004 媒体统计

- 统计项必须可点击；
- 点击后携带对应条件进入视频页；
- 正常秒级扫描中直接显示最终数字；异常更新时允许显示轻量状态。

### FR-HOME-005 常用入口与集合

- 首版提供固定推荐顺序；
- 后续允许用户拖动排序；
- 普通集合和智能集合均可由用户添加为首页模块；
- 首页布局设置支持逐项恢复和恢复默认。

### FR-HOME-006 播放与处理状态

- 迷你播放器是可关闭的配置项目；启用后，只要存在未结束的播放会话，离开播放页即显示，播放结束或用户关闭会话后消失；
- 处理失败以全局入口状态为主，首页只显示轻量提醒；
- 首页不得用错误大卡片长期挤占主要内容。

## 5. 媒体源与扫描

### FR-SOURCE-001 媒体源模型

**状态：已确定。** 每个媒体源至少保存：稳定 ID、名称、授权 URI 或路径、授权模式、存储卷、可访问状态、最后同步时间和媒体统计。

- 媒体内容实体与物理位置分开：同一内容实体可以关联多个文件位置；
- 标签、收藏、播放历史和进度属于内容实体，在多个位置之间共享；
- 去重以物理位置为候选执行比较、保护和删除，删除某个位置不得误删内容实体的其他位置；
- 只有低成本属性形成候选且内容证据足够时才自动合并，证据不足时保持独立位置关系。

### FR-SOURCE-002 添加媒体源

- 首次引导允许“现在添加媒体”或“稍后添加”；用户选择添加时说明全盘扫描、跨目录管理和移动后重定位用途，不在冷启动时强制跳转系统授权页；
- “现在添加媒体”页面以全部文件访问作为推荐主选项，但必须由用户点击后才进入系统授权页；同页提供 SAF 目录选择作为清晰的替代项；
- 全部文件访问必须由用户在 Android 系统授权界面显式开启，应用不得绕过或模拟授权；
- 用户拒绝或未授予全部文件访问时，使用 `ACTION_OPEN_DOCUMENT_TREE` 添加目录并持久化 URI 权限；
- 首次授权后立即在后台建立索引；
- 多个媒体源可分别扫描、暂停、重新授权和移除；
- 全部文件访问是首版默认授权模式；SAF/MediaStore 是拒绝授权后的完整降级路径；
- 降级后保留 SAF 授权范围内的播放、媒体库和整理，只限制全盘扫描、跨授权目录移动及全局重定位；
- 媒体源只支持本地目录、SD 卡和 USB 等可移动存储，不支持网络源。

### FR-SCAN-001 扫描体验

**状态：已确定。** 扫描目标是秒级完成，正常情况下不显示加载进度或扫描等待页。

- 进入应用时执行增量同步；
- 提供手动全量扫描用于修复索引；
- 扫描不阻塞已有媒体的浏览和播放；
- 新发现媒体增量进入列表；
- 缩略图和深度元数据不得阻塞轻量索引；
- 有缓存时首屏目标小于 500ms；
- 1 万条媒体的增量轻量索引目标小于 3 秒；
- 正常秒级扫描不显示持续进度或等待页；只有实际超过设备基线、权限异常或解析异常时，才显示非阻塞的轻量更新状态，并按需要提供取消和诊断入口；
- 首次无缓存时显示结构化骨架和“正在建立媒体库”文字，不显示虚构百分比；选择“稍后添加”时直接进入带添加入口的空首页；
- 初次全量扫描仍先完成轻量索引，缩略图和深度元数据后台补全。

### FR-SCAN-002 异常降级

- 权限丢失时保留索引并标记媒体源不可访问；
- 可移动存储离线时保留标签、历史和播放列表关系；
- 不支持文件按扩展名和原因统计，不加入可播放视频列表；
- 异常耗时才显示非阻塞“正在更新媒体库”和恢复入口；
- 不显示逐文件路径日志。
- 默认排除隐藏目录和隐藏文件，用户可按媒体源开启；
- SD 卡或 USB 重新连接时根据卷标识和授权 URI 恢复原媒体源。

### FR-SCAN-003 文件重定位

- 部分路径授权：只在授权树内重新关联，移出授权树后标记缺失并请求新授权；
- 全部文件访问：可以在其他可访问路径尝试重新定位；
- 用户标题、标签、收藏和历史跟随媒体实体，不跟随单一路径；
- 连续多次扫描确认缺失后，才提供批量清理索引。

### FR-SCAN-004 缩略图

- 首屏可见项优先；
- 其余项目使用受限并发的后台队列；
- 默认抽取前段稳定帧，失败回退首帧；
- 详情页允许重新生成；
- 保险库使用独立受保护缓存。
- 快速滚动时取消离屏低优先任务；
- 普通缓存使用可配置上限和 LRU 清理。

### FR-SCAN-005 索引维护

- 默认排除系统铃声、通知、缓存、应用数据和 `.nomedia` 目录；
- 深度解析优先级为当前可见项、继续观看、最近添加、其他媒体；
- 缺失媒体连续 3 次或超过 7 天后进入清理建议；
- 先使用卷/文档 ID 和文件属性关联位置，只有候选冲突时异步计算内容指纹；
- 普通隐藏实现为可恢复的媒体库排除规则，不提供加密承诺。

## 6. 视频库、搜索与筛选

### FR-LIB-001 浏览方式

- 必须提供全部视频；
- 顶部分组只承载媒体维度，例如全部视频、文件夹/媒体源；标签不作为视频页顶部分组，通过筛选面板或整理页进入；
- 支持文件夹、时长、扩展名等分组或筛选；
- 正式支持网格、缩略图和列表；
- 瀑布流在首版提供入口并明确标记为实验功能，允许关闭、降级或回退到网格；
- 默认使用中等密度网格；
- 网格密度提供少/中/多三档并根据窗口宽度自适应列数。

### FR-LIB-002 媒体卡

- 使用统一 16:9 容器完整适配内容，允许留边，不强制裁切主体；
- 默认显示标题、时长和观看进度；
- 分辨率、文件大小等字段可配置；
- 网格标题最多 1 行，列表最多 2 行；
- 详情和编辑页显示完整标题；
- 观看进度使用无彩细线和文字，不使用成功绿色。

### FR-LIB-003 排序

- 支持最近添加、时长、名称、播放次数等字段；
- 每个字段支持升序和降序；
- 使用有意义的方向文案，例如最短/最长、最旧/最新；
- 名称使用本地化自然排序；
- 视图和排序按视频页内的主分组分别持久化，临时筛选限当前会话或媒体源。

### FR-SEARCH-001 搜索

- 搜索是全局能力，三个一级页面均以搜索图标进入，不常驻搜索框；
- 默认搜索文件名和显示标题；
- 用户可扩展到路径、标签和技术元数据；
- 不提供搜索建议；
- 可以保存可清除的本地搜索历史；
- 结果按视频、文件夹、标签、播放列表和智能集合分组，视频为默认首组；
- 无结果时显示搜索词、搜索范围和恢复操作。

### FR-FILTER-001 筛选容器

- 手机端使用可扩展到全高的模态底部面板；
- 面板使用单一滚动区域，并固定应用/重置操作；
- 分区顺序：当前条件、标签、文件属性、播放状态、路径、排序与视图；
- 视频页顶部显示条件数量和可移除的条件 Chip。

### FR-FILTER-002 多标签逻辑

- 默认要求同时包含全部标签；
- 高级模式允许包含任一标签和排除标签；标签是同字段默认 OR 规则的明确例外，以最后确认的 AND 默认值为准；
- 使用“同时满足/满足任一”完整文字，不只显示 AND/OR；
- 数据模型区分原子标签和一层组合标签：组合标签引用多个原子标签及匹配规则，可在筛选界面像普通标签一样使用，但不允许组合标签继续嵌套；
- 组合标签只表达标签条件；智能集合可以同时保存标签、文件属性、播放状态、排序等完整规则；
- 组合筛选可以保存为智能集合。

## 7. 整理、集合与详情

### FR-ORG-001 标签

- 整理页以标签为主入口；
- 标签按常用和最近使用分区；
- 整理页提供创建/编辑主入口，详情和多选提供快捷入口；
- 标签使用受控色板，高级入口允许自定义颜色；
- 自定义色必须校验可读性并提示与功能色的语义冲突；
- 标签颜色只是辅助线索。
- 组合标签与原子标签使用一致的主要操作方式，但编辑页必须显示其成员和匹配逻辑，避免用户误以为它直接写在视频上；

### FR-ORG-002 收藏、播放列表和集合

| 类型 | 语义 | 更新方式 |
|---|---|---|
| 收藏 | 单项偏好标记 | 用户添加/移除 |
| 播放列表 | 持久播放顺序 | 用户维护，可排序 |
| 普通集合 | 浏览组织 | 用户维护成员 |
| 智能集合 | 保存的筛选和排序 | 条件自动匹配 |

这些类型共用媒体卡和批量操作，但不得在数据模型中互相替代。

### FR-ORG-003 标签变更

- 删除标签前显示受影响视频数量；
- 合并标签时预览目标关系；
- 批量添加/移除后立即更新，并提供统一撤销；
- 部分失败必须列出失败项。

### FR-DETAIL-001 视频详情

信息顺序：预览和播放、标签/收藏、核心媒体信息、文件和编码详情、危险操作。

- 可编辑字段集中在编辑区域；
- 技术字段使用只读定义列表并支持复制；
- 字段标记来自用户编辑、文件解析或推断；
- 显示标题优先级：用户值、嵌入标题、文件名；
- 修改显示标题默认不重命名源文件；
- 文件重命名是独立的文件操作。

## 8. 多选、文件操作与回收站

### FR-SELECT-001 多选

- 长按媒体卡进入多选；
- 应用栏必须另有显式“选择”入口；
- 顶部显示选择数量；
- 底部显示高频批量操作，低频操作进入更多菜单；
- 选择状态可在同一媒体源的文件夹之间保留；
- 短暂进入详情或筛选后返回仍保留，退出媒体源或主动退出时清空。

### FR-FILE-001 文件操作

- 移动和复制是两个独立命令；
- 执行前显示目标路径、预计空间和冲突；
- 批量重命名支持前后缀、序号和替换规则；
- 批量重命名必须预览旧名称到新名称映射；
- 所有操作必须报告成功、失败和跳过数量。

### FR-TRASH-001 回收站

- 影里提供统一的回收站页面和恢复语义；底层优先使用 MediaStore 系统回收站，系统能力或授权范围不满足时使用受控降级实现；
- 普通删除默认进入回收站并提供撤销；
- 回收站显示原路径、删除时间、占用空间和清理倒计时；
- 支持恢复和永久删除；
- 恢复冲突提供重命名、覆盖和跳过；
- 永久删除展示对象、数量、路径和不可恢复后果。

## 9. 播放器

### FR-PLAYER-001 页面主体

**状态：已确定。** 播放页以视频画面为绝对主体。视频画布在浅色、深色和跟随系统模式下均保持纯黑；主题模式只改变控制面板、对话框、系统栏和文字 Token。竖屏信息区默认收敛或按需展开，不得挤压主要画面；技术信息进入详情或辅助面板。

### FR-PLAYER-002 播放会话

- Player 与 MediaSession 必须独立于 Activity 和 Compose 页面生命周期；
- 播放页、迷你播放条、系统通知和锁屏控件共享同一会话；
- 旋转和窗口变化不得重新加载媒体或丢失播放状态；
- 普通视频通知显示标题和中性缩略图；保险库视频隐藏敏感信息。
- 迷你播放器由设置控制；关闭该设置不终止播放会话，只移除应用内迷你控制条，系统通知仍按后台播放规则工作；

### FR-PLAYER-003 控制层

- 无操作约 3 秒后隐藏；
- 暂停、拖动、错误或辅助面板打开时保持显示；
- 进度条独占一行，两端显示当前和总时长；
- 拖动有缓存时显示缩略图，无缓存时只显示时间且不阻塞；
- 首版固定核心按钮，后续开放按钮显隐和排序。
- 双击快进/快退默认 10 秒，可分别设置为 5/10/15/30 秒。
- 播放器锁定后仅保留解锁、播放/暂停和必要的系统返回提示；隐藏其他按钮并禁用画面手势；

### FR-PLAYER-004 手势

- 单击切换控制层；
- 双击中央默认播放/暂停；
- 左右区域双击快进/快退可配置；
- 长按默认临时 2x，松开恢复；
- 左侧垂直手势调亮度，右侧调音量；
- 水平拖动调整进度；
- 反馈显示图标、数值和方向，不用全屏彩色遮罩。
- 左右约 40% 分别承接亮度和音量，中间保留播放与缩放手势；
- 自由缩放后单指用于平移，进度调整改由进度条或双指手势；
- 适应、填充、裁剪和自由缩放状态在当前播放内保留。

### FR-PLAYER-005 轨道与字幕

- 倍速、字幕、音轨和画面比例使用统一底部或侧边面板；
- 字幕先选轨道，再配置大小、位置、样式和延迟；
- 音轨和字幕默认按视频记忆；
- 用户可以改为全局默认；
- 同目录外挂字幕按文件名主体、语言和强制字幕后缀匹配；
- 多个候选存在歧义时由用户选择；
- 编码识别失败时尝试常见编码并提供编码预览，不覆盖原字幕；
- 允许通过系统文件选择器加载目录外字幕，并可持久关联到该视频。

### FR-PLAYER-006 续播与结束

- 首次播放从开头开始；
- 常规视频默认从上次位置前 3 秒恢复，接近开头时钳制为 0；
- 设置中允许关闭 3 秒回退并改为精确续播；
- 接近结尾时轻量确认从头或继续；
- 播放结束显示重播、播放下一个和返回详情，不默认自动跳转；
- 连续播放下一项默认关闭，可按播放列表或全局设置开启；
- 连续播放超过 30 秒或总时长 10%（取较小值）时计为一次播放；
- 播放达到 90% 且剩余不足 2 分钟时标记已看完；
- 已看完视频默认从头播放，同时保留从上次位置继续入口；
- 播放进度在内存实时更新，约每 5 秒及关键生命周期事件写入数据库；
- 无痕播放不写入历史、次数和进度。

### FR-PLAYER-007 队列

- 区分当前列表、持久播放列表和临时队列；
- 队列显示来源；
- 支持拖动排序、移除、从指定位置播放和清空；
- 上一项/下一项来自当前明确播放上下文，不从全库随机选择。
- 临时队列跨重启保存，但只提供恢复入口，不自动播放；
- 外部 Intent 打开的视频默认临时播放，播放完成后返回调用方，不自动加入媒体库；默认仍记录播放历史和进度，无痕播放时完全不记录；
- 队列末尾默认禁用“下一项”；
- “插播下一项”插在当前项之后，播放后继续原队列；
- 播放失败默认停留并显示重试、回退、跳过，播放列表可选择自动跳过。

### FR-PLAYER-008 系统行为

- 默认离开应用后暂停视频；
- 用户明确开启后台播放后才能继续；
- 必须遵守音频焦点；
- 普通视频可以主动进入画中画；
- 应用锁或保险库播放默认禁用外部画中画；
- 解码失败优先自动兼容回退并向用户说明。
- 来电或永久失去音频焦点时暂停，焦点恢复后不自动播放；
- 短暂焦点变化默认暂停，可配置为降低音量；
- 视频可见且正在播放时保持屏幕常亮；
- 耳机拔出或蓝牙断开时立即暂停；
- 多窗口模式保持播放并折叠次级控制。
- 后台播放只保留音频和必要轨道，回到前台后恢复视频渲染；
- 按 Home 键默认不自动进入画中画，设置可开启。

### FR-PLAYER-009 截图与 GIF

- 首版提供当前视频帧截图；
- 截图不得阻塞播放主线程，失败时保留播放状态并给出非阻塞反馈；
- 保存位置、命名和媒体库收录遵循统一导出规则；
- GIF 不进入首版，后续作为视频处理能力交付。

## 10. 视频处理与处理中心

**阶段：后续阶段，不属于首版验收范围。**

### FR-PROCESS-001 职责边界

- 视频处理页负责创建和配置切片、压缩、转换、去重任务；
- 处理中心负责队列、执行状态、结果、日志和失败恢复；
- 项目/编辑状态与一次具体导出任务分开建模；
- 处理能力按“切片 → 压缩/转换 → 去重”顺序交付。

### FR-PROCESS-002 队列

- 同一源视频的重任务默认串行；
- 未开始任务可拖动排序；
- 任务按全部、进行中、完成、失败筛选；
- 任务类型只作为标签，不增加一级页面；
- 任务状态必须持久化；
- 重启后显示继续、重试或清理，不能把重新执行称为断点继续。
- 默认只运行一个重任务，轻量分析可有限并行；
- 低电量或高温时降低并发或暂停可延期任务，前台任务允许用户确认后继续；
- 只有底层真正支持恢复的任务显示暂停，其他任务只显示取消。

### FR-PROCESS-003 任务卡

- 显示任务类型、名称、进度、剩余时间或当前阶段、状态；
- 暂停/继续是当前可执行时的主操作；
- 取消、重试、详情、定位文件为次级操作；
- 无法准确估计时使用不确定进度，不伪造剩余时间；
- 后台通知与处理中心状态一致。

### FR-PROCESS-004 预设与输出

- 压缩提供节省空间、平衡质量、高质量等固定预设；
- 高级页提供格式、分辨率、编码器和质量参数；
- 全局保存默认预设，单次任务可以覆盖；
- 已排队任务保存实际参数快照；
- 默认在源文件所在目录下建立独立 `YingLi-Output` 子目录；权限不足时回退到用户已授权输出目录并解释原因；
- 输出不能静默覆盖源视频；
- 同名默认追加序号，可改为覆盖、跳过或逐项决定。
- 默认优先硬件编码，能力不满足时说明耗时和发热影响并回退软件编码；
- 提交前分析 HDR、字幕和多音轨能否保留，不允许静默丢失；
- 提交前估算临时文件和输出空间，空间不足时阻止任务；
- 元数据默认保留标题、日期、方向和非敏感技术信息，移除位置等隐私字段。
- 压缩预设以质量/体积目标和最大分辨率为核心；
- Media3 稳定输出是首阶段边界，多容器以后通过独立处理后端扩展；
- 无法保留字幕或多音轨时阻止提交，要求选择烧录、单轨或放弃附加轨；
- 处理输出保存“派生自”关系，但使用独立媒体实体。

### FR-PROCESS-005 切片

- 同一源视频下维护多个片段；
- 片段按时间顺序展示；
- 支持勾选、删除、重命名和统一导出；
- 时间轴默认秒级操作，放大后支持帧级微调；
- 支持起止点吸附和手动输入；
- 预览和时间轴优先占用编辑页面空间。
- 编辑状态自动保存草稿，导出任务使用独立参数快照；
- 默认精确切片，同时提供关键帧无损快速切片；
- 允许片段重叠并提示重复导出时长，不自动合并。

### FR-PROCESS-006 去重

- 提供“完全重复”和“相似视频”两个显式检测模式；结果均按重复组展示；
- 并排显示缩略图、时长、分辨率、画幅、大小、路径和相似度；
- 说明建议保留/删除规则；
- 默认勾选建议删除项，但允许改选；
- 支持同步播放、统一时间轴和单项放大；
- 相似模式使用严格/均衡/宽松预设，暂不开放任意阈值；
- 不允许自动删除重复文件，删除前必须人工复核并通过回收站或高风险确认。

### FR-PROCESS-007 失败与临时文件

- 失败详情提供可操作原因、修改预设、重试和日志；
- 主动取消任务时立即清理半成品，但保留可重试任务记录；执行失败时可短期保留诊断文件，按期限自动清理并提供立即清理入口；
- 取消任务后半成品不得加入媒体库；
- 提交任务时提供“完成后加入媒体库”选项并记住默认；输出位于已授权/已监控目录时默认开启，结果页显示摘要并允许撤销入库；
- 完整日志可导出，但默认只显示精简摘要。

## 11. 应用锁与保险库

**阶段：后续独立阶段，不属于首版验收范围。** 首版不得仅实现“隐藏”却使用保险库名称；以下条目在该阶段启动时整体生效。

### FR-SECURITY-001 应用锁

- 支持设备生物识别、设备凭据以及应用密码/图案；
- 应用锁保护应用入口；
- 密保问题只作为低安全级别恢复辅助；
- 冷启动和离开应用超过可配置时长后重新验证，默认 1 分钟，可选立即、1、5、15 分钟；
- 连续失败逐步延长等待时间，但不删除数据；
- 密保问题默认关闭，只能辅助恢复应用锁。

### FR-VAULT-001 保险库边界

- 保险库密钥保存在 Android Keystore；
- 密文容器默认位于应用私有目录，并允许用户迁移到已授权目录；用户授权目录只保存密文，不保存可直接复制使用的密钥；
- 保险库与应用锁分别建模和计时；
- 解锁应用不自动解锁保险库；
- 保险库内容排除普通视频库、搜索、首页、历史、统计和普通缩略图缓存；
- 解锁后只在专属入口显示；
- 默认离开应用即锁定，也支持屏幕关闭和可配置超时。
- 保险库必须是真实加密存储，不提供“仅隐藏”模式；
- 视频进入保险库采用加密、校验、提交后再删除源文件的事务流程；
- 密钥或密文损坏时明确不可恢复，不提供绕过加密的后门。
- 生物识别变更导致认证密钥失效时，必须使用预配置恢复凭据重新绑定；无法验证时内容不可解密。
- 不依赖系统卸载拦截；在启用保险库、导入私密内容和配置备份时提前说明卸载、密钥丢失及不可恢复风险。

### FR-VAULT-002 外部暴露

- 系统媒体控件不显示私密标题、路径和封面；
- 默认禁止保险库视频画中画；
- 分享前必须在保险库内明确确认；
- 用户可以临时导出副本或先移出保险库；
- 保险库页面禁止系统截图，最近任务使用中性遮罩；
- 投屏、画中画和外部媒体控制默认全部禁用，只能由用户逐项开启；
- 播放优先流式解密，必要的临时明文放在受保护目录并及时清理；
- 移出保险库时默认恢复原路径，不可用时选择已授权目录并处理冲突。

### FR-VAULT-003 备份

- 普通备份默认排除私密媒体、解锁凭据和密钥；
- 应用设置、播放数据、收藏、标签、播放列表和智能集合可备份；
- 备份可选加密；
- 忘记备份密码时不得承诺恢复；
- 保险库备份若实现，必须独立选择并二次确认。

## 12. 设置

设置不是一级导航页面，通过顶部全局入口进入。至少包括：

- 外观：浅色、深色、跟随系统；播放器画布固定纯黑，面板跟随所选主题；
- 首页布局：模块显隐、排序和恢复默认；
- 视频库：默认视图、密度、显示字段、排序；
- 播放器：手势、倍速、轨道记忆、画面比例、后台播放、迷你播放器、按钮配置；
- 媒体源：授权、重新扫描、排除路径和异常源；
- 文件管理：回收站期限、默认导出路径、冲突策略；
- 视频处理：默认预设、并行策略、临时文件期限；
- 隐私：应用锁、保险库、历史和无痕播放；
- 备份与恢复；
- 关于与诊断。

设置返回后必须恢复原页面、滚动和筛选状态。

## 13. 数据模型边界

| 实体 | 主要职责 |
|---|---|
| MediaSource | 保存授权范围、卷、状态和同步信息 |
| MediaItem | 表示逻辑媒体及显示标题、技术信息和播放状态 |
| MediaLocation | 表示媒体的一个物理 URI/路径及可访问状态 |
| Tag | 用户标签及受控/自定义颜色 |
| Favorite | 单媒体收藏标记 |
| Playlist | 持久且有序的播放成员关系 |
| Collection | 用户维护的普通集合 |
| SmartCollection | 保存筛选表达式和排序规则 |
| PlaybackRecord | 进度、次数、完成状态和最近播放时间 |
| PlaybackQueue | 当前会话的播放上下文和顺序 |
| TrashEntry | 原位置、删除时间、期限和恢复信息 |
| ProcessingProject | 可继续编辑的切片/处理项目 |
| ProcessingTask | 一次不可变参数快照的执行任务 |
| VaultEntry | 私密媒体引用、加密状态和恢复元数据 |

逻辑媒体与物理位置必须分离，避免文件移动后丢失标签、历史和集合关系。

## 14. 非功能需求

### NFR-PERF-001 启动和扫描

- 有缓存时首页和视频页必须优先显示缓存内容；
- 扫描正常目标为秒级，不出现阻塞式加载页；
- 缩略图和深度解析异步执行；
- 缓存首屏目标小于 500ms，1 万条媒体增量轻量索引目标小于 3 秒；
- 超过性能预算时显示非阻塞状态、取消和诊断入口。

### NFR-PERF-002 播放

- 播放状态不因旋转或 Compose 重组丢失；
- 列表滚动和播放控制目标保持流畅；
- 解码回退、丢帧和温度限制只在异常时提示；
- 文件 I/O、解析、转码和去重不得运行在主线程。

### NFR-ACCESS-001 无障碍

- 正文对比度不低于 4.5:1；
- 大字、图标和交互边界不低于 3:1；
- 交互目标至少 48dp；
- 图标按钮提供语义描述；
- 颜色必须配合图标、文字或形状；
- 字体放大时关键文本和操作不得被截断；
- 首期不专门适配键盘、鼠标、遥控器和 Android TV。

### NFR-PRIVACY-001 隐私

- 不采集行为遥测；
- 不依赖云端账户完成核心功能；
- 诊断日志默认本地保存并隐藏敏感路径；
- 私密内容不进入系统通知、最近任务预览或普通缓存；
- 广泛存储权限必须有功能必要性说明和明确用户授权。

### NFR-RELIABILITY-001 文件安全

- 普通删除默认可恢复；
- 永久删除和覆盖必须明确确认；
- 批量任务必须提供逐项结果；
- 文件写入优先使用临时文件完成后原子替换；
- 转码和复制在空间不足时不得破坏源文件。

- 首版范围冻结为播放、媒体库和整理基础闭环，并包含截图、实验性瀑布流和默认全部文件访问；
- GIF、视频处理、应用锁与保险库属于后续阶段；
- 新需求必须通过新增编号或正式变更记录进入，不直接改写历史回答。

## 16. 验收设备基线

- 最低支持 Android 12（API 31）；
- 当前指定真机：Xiaomi M2012K11AC，Android 13（API 33）；
- 当前不要求为 Android 8-11 保持兼容；
- 首版只验收上述 Android 13 真机，不把模拟器或其他系统版本列为发布门槛；
- Android 12 及其他受支持版本在实际补测前必须标记为“声明支持但未验证”，不得宣称已经完成兼容性验收。
