使用场景决策 Usage Decision Guide

不是每次要"弹一个东西"都随手选个组件——按场景特征决策。

浮层选型：Dialog / BottomSheet / Snackbar / Menu
Dialog必须做一个决定才能继续，尤其是破坏性操作确认
BottomSheet一组相关操作（3–6 个），从长按或手势触发，触屏更顺手
Snackbar一次性反馈，不阻塞，用户可以忽略，最多配一个操作
Menu从固定图标按钮触发的少量选项（2–4 个），不需要占满屏宽
场景选型理由
长按视频卡片BottomSheet触屏手势触发，选项较多（分享/重命名/移入回收站/添加到播放列表）
顶部栏"更多"图标按钮Menu从固定按钮触发，选项少，不需要占满宽度
永久删除确认Dialog破坏性、不可撤销，必须让用户明确做一次决定
"已移入回收站"反馈Snackbar操作已完成，不阻塞后续浏览，配一个"撤销"
批量操作部分失败的详情Dialog信息量比 Snackbar 一行能装的多，且用户可能需要看完再决定下一步
按钮变体：Primary / Secondary / Tonal / Ghost / Danger
变体场景
Primary页面或对话框里唯一的主要操作
Secondary和 Primary 并列的次要操作，如对话框里的"取消"
Tonal频率高但不是页面重点的操作，如"筛选"
Ghost视觉权重最低，如"清除筛选"这类可有可无的操作
Danger只用于不可撤销的破坏性操作（永久删除），可撤销的"移入回收站"不用这个变体

验收清单 Acceptance Checklist

发布前过一遍。

同一手势（长按、滑动）在同类场景里含义一致，没有前后矛盾
浮层选型对照「使用场景决策」表逐个检查，没有随手选的 Dialog/BottomSheet
破坏性操作只用 Danger 按钮，可撤销操作没有误用 Danger 样式
组件的可选部件（如缩略图卡片的观看进度条）在没有数据时正确隐藏，不留空白占位
滑动手势的触发阈值在真机上测试过，没有和滚动手势冲突
长按进入多选模式后，有清楚的退出方式（再次长按 / 返回键 / 取消按钮）
