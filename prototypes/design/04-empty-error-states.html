没有内容，
也要说清楚为什么。

空状态是"这里还没有东西，但一切正常"；异常状态是"出问题了，需要你知道"。两者用不同的视觉语言区分——空状态用中性灰阶徽标，异常状态用语义色徽标，插图统一用线性图标而不是彩色插画角色，和 02 文档"克制、灰阶为主"的气质保持一致，也不需要额外维护一套插画资产。

空状态 ≠ 异常状态没有内容是正常状态，不用警示色
四级呈现全屏 / 区块内 / 列表内联 / 对话框，按影响范围选
线性图标，不做插画复用 icon-xl（32dp）Token，不新增插画资产
文案跟 03 走什么 + 为什么 + 怎么办，中英双语

分类体系 Taxonomy

状态出现的位置决定它的呈现方式——不是每种空状态或异常都要弹一个对话框。

判断顺序：先看影响范围（整个页面 / 页面里的一块 / 列表里的一项 / 单次操作的反馈），再决定用哪一级呈现，而不是先想好一个组件样式再到处套用。

图标与插图风格 Icon & Illustration Style

不做彩色插画角色——一是和"克制、灰阶为主"的视觉气质不搭，二是省掉一整套插画资产的绘制和维护成本。

层级徽标尺寸图标尺寸徽标底色
全屏 Full-page96dp 圆形32dp（icon-xl，沿用 01 已有 Token）空状态：中性灰 --surface-component；异常：语义色容器 --error-container / --warning-container
区块内 Section64dp 圆形32dp同上
列表内联 List-inline40dp 圆形18dp同上，但视觉更轻，通常直接嵌在列表项里而不单独起一行

对话框/Toast 级异常不用圆形徽标——直接用 02 文档定义的语义色图标（--error / --warning），跟对话框标题左对齐即可，不需要额外的徽标底。

空状态 Empty States

8 个场景。徽标统一用中性灰阶，语气平静，不强推操作——大部分空状态本来就不需要按钮。

异常状态 Error & Exception States

9 个场景，按严重程度分 warning（可恢复、不紧急）和 error（阻塞操作）两档，文案遵循 03 文档"什么 + 为什么 + 怎么办"。

影里的定位是离线优先、不接入网络媒体源，所以这份目录里没有"网络连接失败"这类场景——如果之后加同步或云端功能，需要单独补一组网络异常状态。

手机模型演示 In Context

四个层级各挑一个场景放进真机模型（360×780dp，与 01 文档同一个真实设备尺寸）里看实际效果，尤其是"列表内联"——它不是弹窗也不是整块空状态，只影响列表里的一行。

验收清单 Acceptance Checklist

发布前过一遍。

每个列表 / 网格页面都确认过对应的空状态，没有漏掉的"卡在加载中"或纯白页面
空状态徽标统一中性灰，没有误用语义色
异常状态的 warning / error 分级和本文档一致，没有把可恢复问题标成 error 红色
所有异常提示至少说明"是什么"，有已知解决办法的额外给出"怎么办"（对应 03 文档原则）
批量操作的部分失败场景有单独设计，不是简单弹出第一个错误
文件缺失 / 损坏在列表里是内联轻量提示，不是每次都弹对话框打断浏览
权限被拒绝后有清楚的"为什么需要这个权限"说明，不是系统弹窗一关就没有后续引导
