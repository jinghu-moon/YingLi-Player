类型阶 Type Scale

改编自 Material 3 的 15 角色类型阶，按信息密度向下收紧一档；字重沿用既有的 620 / 650 / 660 / 670 语汇。点击任意规格可复制 CSS 变量。

为什么需要这份刻度审计《02-组件配色设计》发现其中散落着 19 种不同字号、9 种不同圆角，均为搭建过程中随手取值，没有统一刻度。这份文档定义的刻度将作为后续收紧 02 文档取值的依据。
与 Kotlin 实现的落差
15 个设计角色，实现只配置了 12 个YingLiTheme.kt 里的 Typography 只覆盖了 12 个 Material 3 角色，字号也和这里不同。最可能被跳过的是 displayLarge / displayMedium / displaySmall——影里信息密度高，全屏级别的大字很少用到，这 3 个角色很可能从未被任何页面引用，直接用了 Material 3 默认值。这只是推测，需要对照 YingLiTheme.kt 实际字段确认，而不是当作结论。

建议核对顺序：① 打开 YingLiTheme.kt，列出实际配置的 12 个角色；② 对照下方表格逐个确认字号是否要收敛到这里的刻度，还是这里的刻度要向实现让步；③ Display 三个角色如果确认未使用，从 Typography() 里去掉，不必强行配置摆设 Token。

间距 Spacing

4dp 基线网格，11 级刻度。点击色条可复制变量。“边距”取页面/卡片级别的大间距档位，“间距”取元素之间的小间距档位，二者共用同一套刻度。

基线例外（明确允许，不是疏漏）：space-3xs 的 2dp 是光学微调，只用于图标与紧邻徽标这类视觉重心的贴合调整，不作为布局间距使用；分割线固定 1px，不随密度或刻度缩放。这两处不遵守 4 的倍数，是刻意的例外，而不是需要被"修正"到 4dp 网格上的漏项。

圆角 Radius

7 级刻度，从锐角到全圆角。播放画面本身及全屏内容使用 radius-none，不裁切视频画面。

圆角映射见每级下方的用途说明（按钮/输入框→sm，卡片/下拉菜单→md，底部面板/对话框→lg，播放画面→none）。02 原型早于这套刻度搭建，里面仍散落着 3/5/6/7px 等未收敛的圆角值，这次只修正了明确的比例 bug（缩略图 16∶10 → 16∶9），逐组件收敛圆角到这套刻度是下一轮单独的工作，这里先不做。

阴影 / Elevation：--shadow-1/2/3 由《02-组件配色设计》定义和维护，01 只消费这三个 Token 渲染自己的预览组件（如 FAB、导出面板），不重复定义 Elevation 层级，避免两处各写一套阴影值。

布局网格 Layout Grid

手机是唯一目标设备，不为平板 / 折叠屏单独设计——但同一部手机在横屏或分屏（Multi-window）时，窗口宽度会跨进 Medium / Expanded 区间，这是应用里真实存在、且已有测试覆盖的状态，不能用"竖屏锁定"一句话打发。

纠正上一版的简化上一版写"除播放页外锁定竖屏，不提供横屏版本"，这与实际实现不符——应用在非 Compact 窗口下会切换到 NavigationRail，且有测试专门覆盖 Expanded 状态。"手机是唯一目标设备"这个前提依然成立：没有为平板做专门优化；但窗口尺寸分级不是平板专属的概念，同一部手机横屏或分屏时，宽度一样会跨进 Medium / Expanded 区间，浏览类页面需要跟着响应，不只是播放页。
窗口尺寸分级与导航切换
窗口分级宽度阈值典型触发场景一级导航
Compact< 600dp手机竖屏（绝大多数时间）底部导航栏，80dp
Medium600–839dp手机横屏、分屏 Multi-windowNavigationRail，侧边
Expanded≥ 840dp大屏手机横屏、分屏展开NavigationRail，侧边

3 项主导航（如"首页 / 视频 / 整理"）在 Compact 下等宽分布；达到 4 项时改为左对齐、图标+文字，避免等宽挤压导致触控区小于 48dp——这条规则需要和实际 YingLiApp.kt 的实现再核对一遍，这里先给出一个不违反触控基线的方向，不代表已confirm 的最终规则。

安全边距、Edge-to-edge 与内容宽度
场景左右安全边距说明
Compact16dp内容撑满，随 NavigationBar/手势条走 safeDrawing 底部 inset
Medium / Expanded24dpNavigationRail 占用左侧固定宽度（80dp），内容区在剩余宽度内居中排布
播放页横屏0，画面撑满安全区沉浸式全屏，状态栏与导航栏自动隐藏，与窗口分级无关，播放页始终如此

媒体网格列数：columns = floor((可用宽度 + 列间距) / (最小卡片宽度 + 列间距))，最小卡片宽度取 150dp，列间距 8dp（紧凑）/ 12dp（标准）。Compact 竖屏通常落在 2 列，Medium 横屏 4 列左右，Expanded 5–6 列——具体以这条公式实时计算，而不是写死断点对应列数。

播放页旋转：竖屏时标题栏、进度条、控制按钮为常规高度（见下节"横屏播放控制栏"）；转横屏后顶部栏隐藏，控制栏合并为沉浸式底部条，3 秒无操作后连同状态栏一起隐藏，点击画面唤出。

组件状态 States

默认规则是：状态只叠加颜色层，不改变几何尺寸——hover / 按下 / 聚焦如果连带改变大小或位置，会让点击变得不可预测，列表也会跳动。

状态几何变化视觉变化
默认 Default—组件基础样式
悬停 Hover无叠加 --state-hover（约 6% 不透明度）
按下 Pressed无叠加 --state-pressed（约 10% 不透明度）
聚焦 Focus无--focus-ring 外描边，2dp 描边宽度，偏移 2dp
禁用 Disabled无前景替换为 --text-disabled，不叠加状态层（不可交互，不需要 hover/press 反馈）
加载 Loading见下方例外内容替换为骨架屏或 Spinner

唯一允许改变几何尺寸的例外：播放进度条滑块默认 12dp，拖拽时放大到 16dp，便于精确抓取（已在「组件尺寸」章节标注）。需要显示文字标签的场景用 Extended FAB（更宽的胶囊形状）承载，不是让默认 56dp 圆形 FAB 变形去塞文字。除此之外，任何组件在任何状态下的宽高都应该和默认态一致。

骨架屏：占位块尺寸与真实内容完全一致（如缩略图骨架用 142×80，和「列表项（含缩略图）」的缩略图同尺寸），背景色 --surface-component，配合 duration-slow（300ms）的呼吸动画，不单独定义尺寸 Token。

图标 Icon Sizes

5 级刻度，24dp 为工具栏与按钮默认尺寸，与既有组件里 Tabler 图标的实际使用尺寸一致。
